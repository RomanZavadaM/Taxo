Taxo / Driver Worktime
Version: 9.1 candidate r7
Candidate date: 2026-09-19
Release type: functional candidate / pre-release
Baseline: Taxo 9.0.1

Taxo 9.1 candidate r7 — контрольна точка модуля «Персонал» і режимів робочого часу.

Основне:
- окремий верхній розділ «Персонал»: Реєстр / Планування / Табель / Звіти;
- масове планування робочих змін для будь-якої посади/ролі;
- масове внесення відпусток, лікарняних та інших відсутностей інтервалами;
- відсутність перекриває робочий план у табелі, але не видаляє історичний маршрут/графік;
- старий табель водія та старий місячний баланс враховують відсутності з нового модуля персоналу;
- внутрішнє сумісництво: кілька ролей одного працівника в день дозволені без точного перетину часу;
- тривалість «8 годин» не перетворюється на вигаданий інтервал 08:00–16:00;
- точні перетини перевіряються по work_segments / worklog / route_segments;
- роль «Водій» не дублюється через employee_shifts, якщо працівник уже пов'язаний з карткою водія;
- П-5 у PDF та Excel, повна легенда 01–30, відкриття сформованого файла одразу;
- П-5 до появи факту бере планові години з графіка/маршруту, а факт має пріоритет;
- окрема модель режимів робочого часу працівника з історією за датою;
- 5-денний, 6-денний, підсумований та індивідуальний режими;
- шаблони 5/40, 6/40, 6/36, 6/24; 6-денний режим не припускає 8 годин щодня;
- тижневий баланс усього персоналу рахує індивідуальну норму, план, факт, відсутності й скориговану норму;
- для підсумованого обліку тижневий Δ позначається як інформаційний; надурочні не визначаються по одному тижню;
- відпустка/лікарняний зменшує норму на години, які за режимом/затвердженим графіком мали бути робочими;
- «План за режимом → місяць» заповнює лише порожні нормативні дні й не дублює маршрути/зміни; для підсумованого обліку автоматичне вигадування змін вимкнено.

Дані:
- r6 додає тільки службову таблицю employee_work_regimes для історії режимів робочого часу;
- існуючі робочі дані не переписуються;
- бази, скани та персональні дані не включаються в релізні пакети.

Стабільний baseline лишається 9.0.1. r7 — наступний source-candidate для експлуатаційної перевірки; stable baseline лишається 9.0.1.

Додатково в r7:
- «План за режимом → місяць» повторно перевіряє ручний запис, маршрут і зміну безпосередньо перед INSERT;
- конфлікт за employee_id + work_date обробляється через ON CONFLICT DO NOTHING;
- повторне застосування не створює дублікати й не падає на UNIQUE;
- додані регресійні тести для повторного запуску та зміни плану між preview/apply.
