Version: 9.1 candidate r9.6
Candidate date: 2026-09-19
Release type: START compatibility hotfix candidate / pre-release
Baseline: Taxo 9.0.1

Taxo 9.1 candidate r9.6 — Windows CMD compatibility hotfix for START.bat.

Основне:
- окремий верхній розділ «Персонал»: Реєстр / Планування / Табель / Звіти;
- масове планування робочих змін для будь-якої посади/ролі;
- масове внесення відпусток, лікарняних та інших відсутностей інтервалами;
- відсутність має пріоритет у табелі, але не видаляє історичний маршрут/графік;
- старий табель водія та старий місячний баланс враховують відсутності з нового модуля персоналу;
- внутрішнє сумісництво: кілька ролей одного працівника в день дозволені без точного перетину часу;
- тривалість «8 годин» не перетворюється на вигаданий інтервал 08:00–16:00;
- точні перетини перевіряються по work_segments / worklog / route_segments;
- роль «Водій» не дублюється через employee_shifts, якщо працівник уже пов'язаний з карткою водія;
- П-5 у PDF та Excel, повна легенда 01–30, відкриття сформованого файла одразу;
- П-5 перед формуванням запитує, чи підставляти план замість відсутнього факту; підстановка завжди явно позначається у документі;
- окрема модель режимів робочого часу працівника з історією за датою;
- 5-денний, 6-денний, підсумований та індивідуальний режими;
- шаблони 5/40, 6/40, 6/36, 6/24; 6-денний режим не припускає 8 годин щодня;
- тижневий баланс усього персоналу рахує індивідуальну норму, план, факт, відсутності й скориговану норму;
- для підсумованого обліку тижневий Δ позначається як інформаційний; надурочні не визначаються по одному тижню;
- відпустка/лікарняний зменшує норму на години, які за режимом/затвердженим графіком мали бути робочими;
- «План за режимом → місяць» заповнює лише порожні нормативні дні й не дублює маршрути/зміни; для підсумованого обліку автоматичне вигадування змін вимкнено.

Дані:
- r6 додає тільки службову таблицю employee_work_regimes для історії режимів робочого часу;
- існуючі робочі дані не переписуються;
- бази, скани та персональні дані не включаються в релізні пакети.

Стабільний baseline лишається 9.0.1. Поточний кандидат r9.6 перевіряється окремо; main не оновлюється до завершення експлуатаційної перевірки.

Додатково в r7:
- «План за режимом → місяць» повторно перевіряє ручний запис, маршрут і зміну безпосередньо перед INSERT;
- конфлікт за employee_id + work_date обробляється через ON CONFLICT DO NOTHING;
- повторне застосування не створює дублікати й не падає на UNIQUE;
- додані регресійні тести для повторного запуску та зміни плану між preview/apply.

Додатково в r8:
- «Табель» і «Графік водіїв» використовують спільний канонічний стан дня;
- вихідний більше не виглядає порожнім рядком на графіку: показується «Вихідний»;
- для робочого дня без часових інтервалів показується «Робота · час не задано», для порожнього буднього дня — «Немає плану»;
- відсутність із табеля персоналу однаково перекриває план у табелі водія та на графіку, не видаляючи історичний worklog/segments;
- додані регресійні тести на сценарій 19.09.2026 та overlay відсутності.

Додатково в r9:
- часові частини дня нормалізуються за порядком початку, а не за попереднім кінцем;
- перекриття 14:10–15:45 + 15:30–17:00 більше не перетворюється на фальшиву перерву 23:45;
- робочий/керувальний час з точних сегментів рахується як об'єднання інтервалів, без подвійного рахунку перекриття;
- для прикладу зі скріншота план роботи стає 8:45 замість 9:00, керування лишається 7:40, конфлікт перекриття — 0:15;
- нове перекриття не можна зберегти ні в робочому дні, ні в маршруті; копіювання дня також не поширює конфлікт;
- місячний баланс, PDF/Excel та табель використовують той самий канонічний розрахунок;
- додані регресійні тести на перекриття, фальшиву перерву 23:45 і нічний перехід через 00:00.

Додаткова синхронізація r9:
- місячний графік змінності та деталізація використовують ті самі канонічні хвилини;
- шляхівка показує канонічні планові години і блокує видачу при перекритті робочих частин;
- аналіз міжзмінного відпочинку коректно нормалізує багаточастинний день через північ.

Контрольна поправка r9.1:
- канонічні інтервали модуля «Персонал» мають локальний fallback для старих/мінімальних core-адаптерів;
- збережена сумісність тестів і старих інтеграцій без дублювання алгоритму на стороні виклику;
- v9.1-r9 лишається незмінним захищеним тегом; r9.1 є новою окремою source/START контрольної точкою.

Додатково в r9.2:
- напис «план перекрито відсутністю» замінено на зрозуміле «План збережено; день позначено як відсутність»;
- пояснення в модулі «Персонал» більше не використовує слово «перекриває» для відсутності;
- у «Графіку водіїв» додано кнопку «Перевірити графіки»;
- аудит перевіряє всі дні водіїв вибраного місяця та всі активні маршрути;
- контроль знаходить перекриття робочих інтервалів, перекриття керування, неповні пари часу та керування поза межами робочого інтервалу;
- знайдені проблеми лише показуються для виправлення — історичні дані автоматично не змінюються;
- подвійний клік/«Відкрити запис» веде до конкретного дня або маршруту для ручного виправлення.

Додатково в r9.3:
- П-5 актуалізовано до структури типової форми № П-5 за наказом Держкомстату України від 05.12.2008 № 489;
- додано стать та оклад/тарифну ставку до картки працівника;
- у щоденному табелі персоналу додано фактичні категорії П-5: надурочні, нічні, вечірні, робота у вихідні/святкові;
- якщо є план без факту, перед формуванням П-5 Taxo питає: підставити план, сформувати лише за фактом або скасувати;
- план, підставлений замість факту, виділяється і супроводжується приміткою у PDF/XLSX;
- архів бланків отримав фільтр за вибраним водієм, опційний відбір за місяцем і сортування новіших записів угорі;
- вікно місячного контролю водія перероблено на інформативну панель із вкладками «Дні місяця» / «Контроль №340» та кнопкою «Відкрити деталізацію»;
- системний аудит графіків з r9.2 збережено.


Додатково в r9.4:
- «Перевірити графіки» перероблено на зрозумілий центр «Аудит графіків…»;
- на головному графіку показується статус поточного дня: помилок немає / кількість знайдених помилок;
- аудит має області «Поточний день», «Весь місяць», «Активні маршрути», «Місяць + маршрути»;
- окремо пояснюється межа між технічним аудитом введення та нормативним контролем Положення №340;
- аудит тепер перевіряє legacy worklog без work_segments, якщо у записі є точні часові межі;
- для дня коректно показується пов’язаний маршрут; активний маршрут без часових частин вважається проблемою;
- порожня частина графіка визначається як помилка введення;
- документація, About, build/spec/installer-реквізити синхронізовані з r9.4;
- Windows/macOS build workflows більше не створюють артефакти зі старими назвами v8.70/r11;
- додано окремий технічний аудит перед переходом до наступного етапу;
- stable baseline 9.0.1 не змінюється; r9.4 публікується як immutable source/START pre-release.

Додатково в r9.5:
- START.bat перевіряє наявність requirements.txt і taxo_app.py до запуску pip;
- якщо START.bat запущено прямо з ZIP і архіватор витягнув лише один файл, Taxo показує зрозумілу інструкцію повністю розпакувати архів замість технічної помилки pip;
- до START-пакета додано 00_README_START.txt з короткою інструкцією першого запуску;
- виправлено формування імен START-архівів для дробових candidate revision: r9.4/r9.5 більше не скорочуються до r9;
- source package workflow тепер окремо перевіряє наявність requirements.txt, taxo_app.py, START.bat, 00_README_START.txt і release_naming.py у ZIP;
- додано regression tests для START guard та release naming;
- функціональний код r9.4 не змінювався; r9.5 є пакувально-запускним hotfix candidate.

Додатково в r9.6:
- START.bat переписано у чистий ASCII без chcp і без не-ASCII тексту всередині BAT;
- START.bat збережено з Windows CRLF для максимальної сумісності cmd.exe;
- українська інструкція лишається окремим UTF-8 файлом 00_README_START.txt;
- додано режим TAXO_START_PREFLIGHT_ONLY=1 для безпечної CI-перевірки повністю розпакованого пакета без встановлення залежностей і запуску GUI;
- Windows CI реально запускає START.bat у повній папці та очікує START preflight OK / exit 0;
- Windows CI окремо запускає самотній START.bat у порожній папці та очікує контрольований exit 2;
- source packaging CI перевіряє, що START.bat ASCII-only, без chcp і містить CRLF;
- додано tests/test_v9_1_r9_6.py;
- r9.5 зберігається як immutable історичний release, але не рекомендується для ручного тестування через Windows CMD parsing regression;
- функціональна логіка r9.4 не змінювалась; r9.6 є лише START compatibility hotfix.
