## Поточний r6

### Персонал
- окремий верхній розділ **Персонал**;
- вкладки Реєстр / Планування / Табель / Звіти;
- стара верхня вкладка уточнена як **Водії**;
- масове планування робочих змін для будь-якої професії/ролі;
- окреме масове внесення відпусток, лікарняних та інших відсутностей;
- режими інтервалу відсутностей: лише робочі планові дні / Пн–Пт / усі календарні дні;
- фактичні години масовими операціями не перезаписуються.

### Внутрішнє сумісництво
- один працівник може мати кілька ролей одного дня;
- точні часові інтервали не повинні перетинатися;
- 07:00–10:00 механік + 11:00–17:00 водій — допустимо;
- «8 годин» без часу — лише тривалість, не 08:00–16:00;
- план без точного часу дає попередження, а не вигаданий конфлікт;
- точні перетини перевіряються через work_segments / worklog / route_segments;
- водійська робота працівника, пов'язаного з карткою водія, не дублюється через employee_shifts.

### Відсутності та сумісність зі старим табелем
- відсутність у employee_time_entries перекриває план у новому табелі персоналу;
- історичний маршрут/worklog не видаляється;
- відпустка/лікарняний відображається також у старому табелі водія;
- старий місячний баланс не додає робочі години дня, перекритого відсутністю.

### П-5
- PDF і Excel (.xlsx);
- повна легенда кодів 01–30;
- календар 1–31;
- дата формування, підрозділ, ЄДРПОУ;
- введені планові години з графіка/маршруту використовуються до появи факту;
- після появи факту факт має пріоритет;
- після формування файл можна відкрити одразу;
- є «Відкрити останній PDF / Excel».

### Режими робочого часу
Додано окрему effective-dated таблицю `employee_work_regimes`.

Підтримуються:
- 5-денний тиждень;
- 6-денний тиждень;
- підсумований облік;
- індивідуальний / інший режим.

Шаблони:
- 5/40;
- 6/40;
- 6/36;
- 6/24.

Важливе правило: Taxo не використовує «8 годин на день» як універсальну норму. Для 6-денного режиму контролюються денні межі відповідно до обраної тижневої норми.

### Тижневий баланс персоналу
Показує:
- норму;
- зменшення через законну відсутність;
- скориговану норму;
- план;
- факт;
- різницю;
- дні без факту;
- режим та примітку.

Для підсумованого обліку тижневий Δ є інформаційним; надурочні визначаються за встановлений обліковий період, а не автоматично за окремий тиждень.

### План місяця за режимом
- заповнює лише порожні нормативні робочі дні;
- не дублює маршрути, зміни або ручні записи;
- для підсумованого обліку автоматичне вигадування змін вимкнене: потрібен реальний затверджений графік.

## Дані та сумісність

- r6 додає лише службову таблицю `employee_work_regimes`;
- існуючі worklog / employee_shifts / employee_time_entries не переписуються міграцією;
- робоча БД, скани, кеші та персональні дані не включаються до релізів;
- робоче сховище лишається сумісним з 9.0/9.0.1; при запуску r6 схема доповнюється автоматично.

## Що тестуємо зараз

1. **6-денний 40-годинний тиждень:** норма дня не повинна автоматично бути 8 год; перевірити 6/40 і власний розподіл.
2. **Відпустка/лікарняний:** масове внесення → новий табель персоналу → старий табель водія → тижневий баланс → П-5.
3. **Внутрішнє сумісництво:** механік/інженер + водій в один день без перетину і з перетином.
4. **План лише за тривалістю:** 8 год без точного часу не повинні створювати вигаданий часовий конфлікт.
5. **П-5:** години з маршрутного графіка, відкриття PDF/XLSX після створення.
6. **Підсумований облік:** тижневий Δ лише інформаційний; не визначати надурочні до кінця облікового періоду.
