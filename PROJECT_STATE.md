## 10.6-r2 — нерегулярні поїздки та UI

- усунуто хибне припущення, що кожен виїзд автобуса повинен мати регулярний маршрут із каталогу;
- якщо робочий день водія не має `route_id`, стандартна дія **«Сформувати / видати PDF»** відкриває сценарій нерегулярної поїздки замість помилки route/stops;
- підтримуються замовлення, одноразові маршрути, розвозки, поїздки по місту, області, міжобласні та інші разові роботи;
- час виїзду/повернення береться з графіка водія;
- якщо автобус не призначено на день, його можна вибрати безпосередньо під час формування шляхівки;
- це призначення записується як **план** робочого дня, не як тахографічний факт;
- поле «Поїздка / замовник» редагується довільно, типове значення — «по області»;
- зворотний бік нерегулярної шляхівки не заповнюється фіктивним маршрутним розкладом;
- для реального каталожного маршруту чинна сувора перевірка route/stops збережена;
- нижня дія має назву **«Інша поїздка / замовлення…»**;
- вікно «Про програму» ущільнене й адаптивне по висоті, щоб нижня кнопка не обрізалась на невисокому/масштабованому екрані;
- межа plan/fact і тахографічний облік не змінені.

## Успадковано з попередніх

- сумісність імпорту XLSX «Шлях» з Windows 7 / Python 3.8 для `tabId`;
- локальний цикл щорічного звіряння військового обліку через Дію без імітації державного API;
- editable working data окремо від immutable державних snapshots;
- покомпонентна звірка ТЗ з «Шлях»;

- військово-транспортна відомість підприємства;
- контроль документів ТЗ, ДЦВ, кількох документів одного типу, ручного архівування;
- правила plan/fact, бланки підтвердження діяльності, табелі, графіки та шляхові листи.

## Обов’язкове версіювання

- кожен завершений крок = нова ревізія `r1 → … → r10`;
- після `r10` — наступна minor-версія з `r1`;
- уже видану ревізію не перевидавати і не пересувати;
- major-розряд змінює тільки власник;
- після виданого `10.6-r2` будь-яка нова кодова зміна — тільки **10.6-r3**;
- «злити у main» = перевірки → пакети → tag/release → PR → merge → синхронізація документації.

## Постійні межі даних

- робочі БД, SQLite, скани, кеші та персональні документи не публікуються;
- оновлення програми не повинно стирати або підміняти робочі дані;
- державні XLSX/CSV — джерело звірки/доповнення, а не заміна робочої БД;
- raw snapshots державних витягів не переписуються локальними змінами;
- порожнє значення в держреєстрі не видаляє локальне значення автоматично;
- локальне редагування в Taxo не означає зміну даних у Дії, «Оберіг» або «Шлях»;
- імпорт державного XLSX сам по собі не означає офіційно завершене звіряння;
- планові дані не оголошуються фактом без явного підтвердження.
