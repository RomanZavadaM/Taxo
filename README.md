## Статус продукту

**Taxo 9.0 — поточна стабільна експлуатаційна версія.**

Після випуску 9.0 проєкт переходить у режим практичної експлуатації та накопичення реальних даних. Наступні зміни виконуються насамперед за результатами роботи персоналу: виправлення дефектів, уточнення розрахунків, покращення зручності та лише потім нові функції.

Stable baseline: `v9.0`  
Commit: `a8e6b80d34d114e6d2c82f602d03468f1529e98a`  
Platforms: **Windows x64 / macOS arm64 / macOS x86_64**

## Що робить Taxo

Taxo об’єднує в одному робочому середовищі:

- реєстр працівників і водіїв;
- каталог автомобілів та історію одометра;
- маршрути з точними часовими сценаріями;
- графічне планування роботи водіїв;
- місячний табель водіїв із поділеними змінами;
- загальний табель персоналу «план / факт»;
- формування й облік шляхових листів № 1-АП;
- Бланки підтвердження діяльності у DOCX/PDF/JPG;
- модуль перегляду й контролю аналогових тахокарт;
- контроль робочого часу та керування одного водія;
- 60-денний похвилинний реєстр діяльності;
- звіти PDF/Excel;
- резервні копії та переносиме робоче сховище.

Докладніше: [Опис системи та основного функціоналу](docs/system/SYSTEM_OVERVIEW.md).

## Основні принципи

**План ≠ факт.** Графік/табель і тахографічний факт не змішуються автоматично.

**Невідоме ≠ відпочинок.** Якщо для 60-денного реєстру немає достатнього джерела, проміжок залишається `Невизначено`.

**Історія не стирається безслідно.** Для документів використовуються ревізії, події, архівування та контрольоване анулювання/вилучення.

**Дані відокремлені від програми.** БД, скани й документи живуть у робочому сховищі та не включаються у GitHub Release.

## Ключові можливості 9.0

### Робочий час і контроль

У `Підсумки та контроль №340` для одного водія окремо показуються:

- тижневий робочий час і баланс до **60:00**;
- тижневе керування і баланс до **56:00**;
- середній робочий час за 4 календарні місяці;
- реалізовані перевірки перерв і відпочинку.

Водія можна змінити прямо у вікні контролю. Дата формування PDF задається користувачем.

### 60-денний реєстр діяльності

Окремий PDF розписує 60 календарних днів до хвилини: керування, інша робота, готовність, перерви, відпочинок, відсутність і невизначений час. Кожна доба контролюється до **24:00**, а для інтервалів вказується джерело даних.

### Шляхові листи

Форма № 1-АП формується як векторний PDF. Підтримуються серії/пули номерів, рейси через північ, ревізії, анулювання, одометр, плановий пробіг та архів документів.

### Аналогові тахокарти

Модуль `ТАХО` працює зі сканами, інтервалами, автоматичними кандидатами та ручним підтвердженням. Тахографічний факт не переписує плановий табель.

## Встановлення

### Для звичайної роботи

Відкрийте [GitHub Release v9.0](https://github.com/RomanZavadaM/Taxo/releases/tag/v9.0) і виберіть:

- `Taxo_v9_0_Setup_Windows_x64.exe` — інсталятор Windows;
- `Taxo_v9_0_Windows_x64_Portable.zip` — portable Windows;
- `Taxo_v9_0_macOS_arm64_Portable.zip` — Apple Silicon;
- `Taxo_v9_0_macOS_x86_64_Portable.zip` — Intel Mac.

### Для тестового запуску з коду

`Taxo_v9_0_START.zip` містить вихідний код і `START.bat`. Потрібен Python 3.13.

Після розпакування на Windows запустіть `START.bat`.

## Робоче сховище

За замовчуванням робочі дані розміщуються в `Documents/DriverWorktime`. Через `Файл → Робоче сховище…` можна вибрати локальну, мережеву або синхронізовану папку.

У сховищі зберігаються обидві SQLite БД, скани, вихідні документи, шляхівки, архіви, backups і logs.

Для спільного сховища використовується **послідовний доступ**. Якщо це OneDrive/Dropbox/Google Drive: закрийте Taxo на першому ПК, дочекайтеся синхронізації, потім відкривайте на другому.

Докладніше: [Дані, сховище та резервування](docs/system/DATA_STORAGE.md).

## Безпека даних

Репозиторій і релізи **не повинні містити** робочі БД або персональні дані. Release workflow перевіряє відсутність `.db`, `.sqlite` і `.sqlite3` у пакетах.

Не публікуйте у відкритих Issues реальні БД, скани тахокарт або документи працівників. Для відтворення проблеми використовуйте знеособлені приклади.
