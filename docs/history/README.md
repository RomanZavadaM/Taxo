# Історичні матеріали Taxo

До випуску 9.0 репозиторій накопичив багато checkpoint, test report, publish status, release notes і patch-файлів гілки 8.x.

Вони залишаються корисними для аудиту розвитку та відновлення контексту, але **не є поточною експлуатаційною документацією**.

## Поточні документи

Для актуального стану використовуйте:

- `../../README.md` — головна сторінка продукту;
- `../README.md` — індекс документації;
- `../system/DEVELOPMENT_STATE_v9.0.md` — технічна контрольна точка 9.0;
- `../../VERSION.txt` — коротка машинно/людиночитна версія;
- `../../RELEASE_NOTES_v9_0.md` — release notes 9.0.

## Історичні файли у корені

Файли з префіксами нижче належать до історії 8.x:

- `CHECKPOINT_v8_*` / `CHECKPOINT_V8_*`;
- `PUBLISH_STATUS_v8_*`;
- `TEST_REPORT_v8_*`;
- `PATCH_v8_*`;
- `RELEASE_NOTES_v8_*`;
- старі release approval/channel/ready markers.

`PROJECT_STATE.md` і `CHECKPOINT_CURRENT.md` після впорядкування документації мають вказувати на актуальний stable 9.0, а не використовуватися як хронологічний журнал усіх старих кандидатів.

## Чому старі матеріали не видаляються одразу

Git уже зберігає повну історію, але на першому етапі стабілізації 9.0 старі файли залишено, щоб не втратити зручні прямі посилання з попередніх обговорень і PR.

Під час окремого технічного прибирання їх можна перемістити в `docs/history/8.x/` без зміни робочого коду. Це косметична операція й не повинна змішуватися з функціональними виправленнями.
