# Контракт взаємодії Taxo ↔ бібліотека шаблонів ↔ картотека документів

**Дата:** 13.11.2026 · **Статус:** проєкт v1 для перевірки, не реалізація.  
**Пов'язаний документ:** [архітектура 13.11](TEMPLATE_LIBRARY_AND_DOCUMENT_ARCHIVE_ARCHITECTURE_2026-11-13.md).  
**Сумісність:** `src/taxo/workspace.py`, `paper_document_store.py`, `document_catalog.py`, `safety_templates.py`, `briefing_preparation.py`, [попередній проєкт сховища](TEMPLATE_LIBRARY_AND_DOCUMENT_VAULT_ARCHITECTURE_2026-11-11.md), [схема одного шаблону](template_import_schema_v1.json).

## 1. Головна домовленість

**Taxo керує роботою; бібліотека містить дані шаблонів; картотека фіксує результат.** Інтерфейс Taxo не знає деталей ZIP/JSON і не записує напряму у файли бібліотеки чи нові таблиці. Вхід через обмежений сервіс; `main.py` тільки створює сервіс і відкриває відповідне вікно. Логіка у feature-модулях, документованих для іншого програміста.

Бібліотека за замовчуванням у `<load_workspace_root()>/TemplateLibrary`; параметр шляху може вказувати інше місце. У робочому просторі вже є чинні `Data/PaperDocuments/index.json`, `Data/driver_worktime.sqlite3`, `Output/` і `Backups/`. **`Data/DocumentVault` — запропонована фізична область для нового архіву згідно з попереднім проєктом; не створювати другий фізичний `DocumentArchive`.**

У публічному Taxo фіксується **тільки контракт і тестовий штучний пакет**; приватні авторські тексти бібліотеки не переносяться в GitHub Taxo.

## 2. Стан бібліотеки й налаштування

### Проста модель статусу

| Статус | Значення | Поведінка UI |
|---|---|---|
| `NOT_INSTALLED` | Немає підключеного чинного manifest | Taxo працює; кнопки, які вимагають бібліотеки, показують «Картотеку шаблонів не встановлено»; старі можливості не ламаються |
| `AVAILABLE` | Manifest і пакет перевірені, потрібні файли доступні | Показати каталог, версію, наявні редакції |
| `INCOMPATIBLE` | Формат новіший за підтримуваний або мінімальна версія Taxo не виконана | Не імпортувати, показати причину й версію |
| `DAMAGED` | Неповний manifest, помилка hash, небезпечний шлях, файл відсутній | Не відкривати небезпечний контент, запропонувати відновити пакет |
| `UNAVAILABLE` | Підключена зовнішня/мережева папка тимчасово недоступна | Не створювати на її місці порожню бібліотеку і не втрачати шлях; повторити підключення |
| `READ_ONLY` | Читання доступне, запис заборонений | Дозволити перегляд; зміни пропонувати лише в окремому доступному сховищі після явного вибору |

Статус не зберігається як остаточний факт; він обчислюється з manifest, доступності й перевірок. Дефолтний шлях і поточний override — окремі налаштування. Порушений шлях не змінює існуючий `workspace_root` і не запускає незаплановану міграцію робочої БД.

### Псевдоконтракт для реалізації

```python
from dataclasses import dataclass
from pathlib import Path
from typing import Optional, Tuple

@dataclass(frozen=True)
class LibraryLocation:
    workspace_root: Path
    library_root: Path
    is_custom: bool

@dataclass(frozen=True)
class LibraryHealth:
    state: str                # значення з таблиці вище
    package_version: Optional[str]
    message: str             # зрозуміле людині пояснення
    is_readable: bool
    is_editable: bool

class TemplateLibraryService:
    def status(self) -> LibraryHealth: ...
    def list_categories(self) -> Tuple[object, ...]: ...
    def list_templates(self, category_id=None, query="") -> Tuple[object, ...]: ...
    def get_revision(self, template_id: str, revision_id: str) -> object: ...
    def create_company_revision(self, template_id: str, base_revision_id: str, edited: object, expected_head: str) -> object: ...
    def validate_install_package(self, archive_path: Path) -> object: ...
    def install_package(self, validated_package: object, explicit_target: Path) -> object: ...
    def propose_move(self, target_root: Path) -> object: ...
    def confirm_move(self, verified_plan: object) -> LibraryLocation: ...
```

Це **не готовий Python-код і не зобов'язання зберегти саме ці типи/назви**. Контракт описує межі й потрібні результати. Методи установки та переміщення не повинні виконувати незворотні дії лише під час попереднього перегляду.

### Особливі гарантії

- `list_*` і `get_revision` — read-only; відсутність бібліотеки повертає зрозумілий стан/помилку домену, не Python stacktrace користувачу.
- `create_company_revision` завжди створює **нову** редакцію у просторі підприємства. `expected_head` захищає від тихого перезапису змін іншого користувача.
- Бібліотека постачальника ніколи не змінюється редагуванням користувача.
- Зміна шляху використовує копіювання → звірку файлів → атомарну зміну конфігурації. Проміжна помилка залишає старий шлях активним.
- Для network/cloud workspace дотримуватися чинного блокування Taxo, не вдавати транзакційність за відсутності її гарантій.
- Використання `Path.cwd()` або шляху EXE замість `workspace.load_workspace_root()` заборонене.

## 3. Дані каталогу: постачальник, підприємство, документ

**Три окремі ID:**
- `template_id`: незмінна тотожність шаблону (наказ про закріплення, повторний інструктаж тощо);
- `revision_id`: конкретна редакція з вмістом та хешем;
- `document_id`: створений за шаблоном **фактичний** документ конкретного підприємства.

**Постачальний пакет:** `package_id`, `package_version`, `format_version`, `min_taxo_version`, `manifest_hash`, перелік item ID → файл/hash. Формат `template_import_schema_v1.json` описує **один item**, тому кореневий manifest каталогу — окрема схема. **Не ламати існуючу v1 схему, якщо вистачає адаптера.**

**Редакція підприємства:** новий immutable запис `company_revision_id`, `based_on_template_id`, `based_on_revision_id`, `editor`, `created_at`, `content_hash`, статус `draft/published/archived`. Відсутність користувацьких ролей у поточній установці Taxo не дозволяє вигадати існуючий механізм авторизації. Коли ролей немає, в UI не показувати фальшивий ACL.

**Готовий документ:** дані реквізитів на момент оформлення, знімок заповненого змісту, посилання на revision (для походження), вкладення, стан, події. Якщо бібліотека видалена, історичний документ **залишається читабельним** завдяки незалежному snapshot.

## 4. Генерація документа: два чіткі переходи

```text
Вибрати шаблон
    ↓ get_revision(id, revision) — read-only
Ввести/підставити факти Taxo
    ↓ render_draft(...): перевірка полів, умов, формату
Попередній перегляд + ручні коригування
    ↓ confirm_document(...): тільки після явної дії
Збережена версія документа + зафіксований snapshot + файли
    ↓ пізніше, окремо: скан / підпис / додаток
Картка історії документа
```

`render_draft` не створює наказ у робочій БД, не встановлює `paper_signed`, не змінює графіки, не додає `training_session` і не записує документ в архів.

Псевдоконтракт:

```python
class DocumentPreparationService:
    def render_draft(self, template_revision: object, facts: object) -> object: ...
    def validate_draft(self, draft: object) -> object: ...
    def confirm_document(self, validated_draft: object, action_context: object) -> object: ...

class DocumentArchiveService:
    def read_card(self, document_id: str) -> object: ...
    def list_cards(self, filters: object, page: int = 0) -> object: ...
    def attach_file(self, document_id: str, attachment: object) -> object: ...
    def read_history(self, document_id: str) -> object: ...
```

**Межа з існуючими наказами:** якщо створення наказу вже робить `operations_orders`, `confirm_document` викликає відповідний існуючий сервіс через адаптер. **Не створювати другий авторитетний реєстр наказів.** Архів фіксує посилання `source_kind=order, source_id=<existing-id>` і власний immutable snapshot.

**Підготовка vs факт:** створений наказ/лист інструктажу не означає, що наказ підписано, інструктаж проведено або учасник ознайомився. Зміна бізнес-факту — окрема явна дія з audit trail.

## 5. Каталог готових документів: еволюція чинного коду

Зберегти `document_catalog.py` як єдиний агрегований перегляд джерел: наявні `operations_orders`, `Data/PaperDocuments/index.json`, а після створення vault — `Data/DocumentVault`. Додати джерело-адаптер, а не запровадити друге вікно «архів» із власною копією наказів.

**Правила тотожності/дедуплікації:** якщо один і той самий наказ є у SQLite, індексі паперових документів і vault, UI показує **одну логічну картку** зі списком походжень/файлів. Стабільний ключ `source_kind + source_id`, а не назва файла/дата. Якщо два записи схожі лише за номером і датою, **не зливати** автоматично. Джерела зі зламаними файлами не приховують інші документи.

Імпорт старих `index.json` — лише після окремої міграційної перевірки: ідемпотентність, `legacy_source/legacy_id`, контроль безпеки шляху та видимого результату. Документи з legacy-папок фізично не переносити без потреби.

**Вкладення:** усі оригінальні байти незмінні; видиму заміну реалізувати новим attachment із `supersedes_file_id`. Скан паперового підпису, файл електронного підпису, результат криптографічної перевірки — різні поля/сутності. `signature_file_attached_unverified` ніколи не дорівнює `verification_passed`.

## 6. Єдина програма інструктажів: контракт

```python
class TrainingProgramService:
    def read_active_company_program(self, company_id: str) -> object: ...
    def list_topic_slots(self, program_revision_id: str) -> tuple: ...
    def propose_topics(self, company_id: str, period: object, target_group: object) -> tuple: ...
    def prepare_session(self, program_revision_id: str, topic_revision_id: str, people: tuple, date: object) -> object: ...
    def record_completed_session(self, validated_evidence: object) -> object: ...
    def list_participant_history(self, employee_id: str) -> tuple: ...
```

- Одна затверджена програма на підприємство, цикл **8 кварталів / 24 місяці**; окремі обов'язкові теми можуть повторюватися за затвердженим планом, а не тільки `not previously seen`.
- Теми мають `topic_id + revision_id`, зміст, тривалість, групи учасників, нормативну/внутрішню підставу, стан перевірки. Не видавати навчальні приклади за чинну нормативну програму.
- `propose_topics` пропонує, **але не призначає і не фіксує факт**. Для позапланових інструктажів окреме джерело події та причина; не «витісняє» обов'язковий плановий захід.
- `prepare_session` повертає попередній перегляд, список фактичних учасників і матеріали; `record_completed_session` приймає **фактичні докази** й не вважає генерацію CSV/DOCX фактом.
- Якщо працівник прийшов у середині циклу, його історія не підмінюється загальним графіком підприємства. При переведенні між групами потрібен явний перегляд, які теми застосовні.
- Не змінювати наявні `briefing_preparation.prepare_list`, `quarter_for`, `shift_quarter` без окремого поведінкового regression.

## 7. Помилки, відновлення і UX

**Публічні доменні помилки** (назви попередні): `LibraryNotInstalled`, `LibraryUnavailable`, `LibraryIntegrityError`, `LibraryFormatMismatch`, `RevisionConflict`, `MissingTemplateVariable`, `UnsafeAttachment`, `ArchiveWriteFailure`. Виняток UI обробляє в конкретному вікні, не закриває весь Taxo.

- Відсутня бібліотека: показати її шлях, «Встановити бібліотеку», «Вибрати іншу папку», «Пізніше»; без нескінченного попередження при кожному відкритті вікна.
- Неповний архів: заборонити установку до повної перевірки та показати конкретний файл/причину.
- Конфлікт двох редакторів: залишити обидві чернетки, запропонувати зберегти як нову редакцію або порівняти; без `last write wins`.
- Переміщення бібліотеки: verify-before-switch, старий шлях зберігається до успіху; в разі збою — повідомити й дати повторити.
- Архівна помилка після підготовки документа: не показувати «збережено», а запропонувати повторити без створення дубліката; потрібен ідемпотентний operation ID.
- Вікно має «Закрити/Скасувати», коректний X і попередження про незбережені зміни; застосувати актуальний UI audit та DPI gate.

## 8. Плани тестів і критерії приймання

| Тест | Критерій |
|---|---|
| Немає `TemplateLibrary` | Taxo відкривається, показує статус і не змінює робочі дані |
| Неправильний manifest/несумісний формат | Жоден файл не встановлений частково; зрозумілий опис помилки |
| ZIP path traversal, symlink, zip bomb, макроси | Reject до розпакування у робоче сховище; жодного виконання |
| Змінити дефолтний шлях на інший | Перевірена цілісність, новий шлях активний, старий не очищений без явного підтвердження |
| Від'єднати мережевий диск | `UNAVAILABLE`; налаштування й оригінали не стираються |
| Редагувати vendor-шаблон | Створюється company revision, vendor незмінний |
| Оновити vendor package | Company revisions і видані документи байтово незмінні |
| Той самий наказ у двох джерелах | Одна логічна картка з обома походженнями, без автоматичного хибного злиття |
| Видалити бібліотеку після випуску | Архівований документ відкривається з snapshot та вкладеннями |
| Підготувати інструктаж | Немає автоматичного факту проведення, підпису чи закриття обов'язку |
| Два роки / 8 кварталів | Вибір різних тематик за планом, обов'язкові повтори не пропускаються |
| Скан додано без КЕП | «Скан додано», без «підпис криптографічно перевірено» |
| Файл КЕП є, валідатора немає | `unverified`, а не `valid` |
| 1/10/50/100+ сторінок | Без усічення, збережені вкладення, коректні DOCX/PDF |
| backup → restore | Зв'язки, snapshots, редакції й **усі включені** файли збігаються SHA-256 |
| UI на 900×600 / Windows DPI 100–150% / macOS / Win7 | Кнопки й навігація доступні, X не закриває всю програму |
| Регресійні тести існуючих наказів | Старий друк/збереження/історія незмінні |
| Структура Python-коду | Нові сервіси не додають бізнес-логіку в `main.py`; модулі мають docstring і типізовані інтерфейси |

Тести на вигаданих даних; не додавати персональні документи до CI.

## 9. Порядок майбутньої реалізації

1. **Схеми й чисті моделі** (`TemplateRevision`, `LibraryHealth`, `TrainingTopic`, `DocumentSnapshot`) із тести формату; жодної схеми БД у цьому кроці.
2. **Read-only adapter** до вже існуючих template-полів, і визначення шляху через `workspace`.
3. **Offline library package reader/validator**, без автооновлення з Інтернету.
4. **Company revisions** із безпечним конкурентним редагуванням.
5. **Документний pipeline** із preview і snapshot; підключення до наявного каталогу, не дублювати замовлення/накази.
6. **Training rotation** і фіксація факту — після окремого нормативного огляду й тестів.
7. **Installer integration** як окрема security/release зміна.

**Кожна кодова ревізія лише за стандартним процесом Taxo.** Цей документ — завершений контракт для обговорення, не реліз і не початок `10.18-r5`.

## 10. Питання, залишені відкритими свідомо

- Де саме зберігати `CompanyTemplates` у межах вибраного workspace, якщо базову `TemplateLibrary` винесли на інший диск? Попередня пропозиція: company revisions залишаються прив'язаними до **робочого простору підприємства** (резервуються з його даними), а постачальну бібліотеку можна переміщати окремо.
- Права й джерела матеріалів у приватному репозиторії мають бути підтверджені до включення їх у дистрибутив; нинішні тексти `safety_templates.py` не стають автоматично затвердженими юридично.
- Чи потрібна одночасна робота кількох користувачів у бібліотеці з мережевого workspace? У випадку такої роботи потрібні перевірені блокування та optimistic concurrency.
