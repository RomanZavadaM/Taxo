# Taxo 10.18-r6 — проєкт інтеграційного кроку бібліотеки (без реалізації)

**13.11.2026.** Цей документ не видає ревізію `r6`, не змінює код, версію, БД чи реліз. Впровадження дозволене **після публікації та перевірки Pre-release `v10.18-r5`**. Поточний точний перевірений source-кандидат r5: `7ee89f3f0dcb731c4b2fd416b6ddb630e3ebe7d2`; його не редагувати повторно.

## 1. Після r5: що є, чого ще немає

**Є:** `template_library_reader.py` (read-only), `inspect_library(root, taxo_version)`, `default_library_root(workspace_root)`; стан `NOT_INSTALLED/AVAILABLE/INCOMPATIBLE/DAMAGED/UNAVAILABLE`; `TemplateSummary`, `LibrarySnapshot`; синтетичні тести, 1242/1242 CI pass на точному r5 head.

**Немає:** налаштування нестандартного шляху, власне UI перегляду каталогу, механізму встановлення ZIP, корпоративного редагування, шаблонізатора, архіву готових документів і ротації навчання. Отже UI r6 **не повинен** створювати враження, що бібліотека вже може сформувати наказ чи документ.

## 2. Єдиний невеликий slice r6

**Мета:** зробити стан бібліотеки зрозумілим користувачу через Taxo, не змінюючи існуючих наказів чи документів. Відкрити **окреме вікно перегляду бібліотеки** через тонкий адаптер в існуючій навігації, який використовує сервіс; показати статус, версію, категорії й список шаблонів.

Пропоновані логічні компоненти (точні імена — після перевірки актуального layout):
- `template_library_service.py` — адаптер налаштувань / `workspace.load_workspace_root()`, виклик `template_library_reader`, підготовка лише читабельної моделі стану; ніякого Tk/SQL;
- `template_library_ui.py` — окремий `Toplevel`, список/фільтр категорій, назва/редакція шаблону, кнопки `Оновити`, `Закрити`; UI не читає manifest/файли напряму;
- існуюча точка меню у Taxo — **мінімальний виклик** `open_template_library(...)`; не додавати парсинг, пошук, форматування або мережеві операції до `main.py`.

**Не робити «заради акуратності»** перенесення великого наявного UI, зміни `document_catalog_ui.py`, генерації DOCX або міграції `Data/PaperDocuments`.

## 3. Розміщення бібліотеки й налаштування

- Стандарт — `<active Taxo workspace>/TemplateLibrary`. Брати активний корінь через `workspace.load_workspace_root()` або контекст того самого активного workspace; **не** `Path.cwd()`, `sys.executable` чи директорію інсталяції.
- Налаштовуваний шлях — окремий явний параметр, який не змінює загальний `workspace_root`. Для першого етапу можна показувати фактичний шлях і кнопку `Вибрати іншу папку`, але не активувати кнопку до реалізації контрольованої процедури збереження налаштувань.
- **Vendor і company data мають різні шляхи**: користувацькі редакції підприємства залишаються в робочому просторі, а каталог постачальника може бути на іншому диску. Встановлення vendor-пакета не створює другу SQLite і не знищує company revisions.
- Не створювати папку `TemplateLibrary` автоматично під час статусного read-only огляду. Для відсутньої бібліотеки показати `Не встановлено`.

## 4. Точна поведінка вікна

| Вхідний стан сервісу | Що бачить користувач | Доступні дії |
|---|---|---|
| `NOT_INSTALLED` | «Картотеку шаблонів не встановлено», шлях до очікуваної папки; Taxo загалом працює | «Закрити», «Оновити»; встановлення відкладене |
| `AVAILABLE` | Версія пакета, категорії, назви, редакції, пошук/сортування | Перегляд, пошук, «Закрити», «Оновити» |
| `INCOMPATIBLE` | Потрібна версія Taxo / непідтримуваний формат | «Закрити», без спроб відкрити зміст |
| `DAMAGED` | Зрозуміла причина пошкодження/невідповідності контрольних сум | «Закрити», «Оновити»; ніякого автоматичного лікування |
| `UNAVAILABLE` | Папка недоступна, збережений шлях лишається попереднім | «Закрити», «Повторити» |
| `READ_ONLY` (майбутній режим) | Перегляд доступний, змінити пакет неможливо | Лише перегляд; не обіцяти редактор |

У кожному стані: X закриває **тільки** дочірнє вікно; повторне відкриття працює; жодних модальних нескінченних попереджень. Якщо дані змінювалися — попереджати перед виходом; у r6 read-only змін немає. При закритті під час читання заборонено оновлювати знищений Tk-widget. Не читати великі пакети з мережевого workspace синхронно в UI thread; обмежений worker та generation-token або вже перевірений механізм з `document_catalog_ui.py` — **не копіювати його без аналізу**.

Для 900×600 / 100–150% DPI: доступна нижня кнопка «Закрити»; вертикальна/горизонтальна прокрутка; видно версію та стан; сортування заголовків за загальним `table_sorting.py`, якщо воно сумісне з моделлю. Користувач не повинен чекати великий каталог, щоб закрити вікно.

## 5. Контракти й межі модулів

```text
current Taxo navigation
    -> template_library_ui.open_template_library(parent, context)
       -> TemplateLibraryService.snapshot()
          -> template_library_reader.inspect_library(library_root, version)
          -> immutable LibrarySnapshot
       -> render(snapshot)  [Tk only here]
```

Публічний API повинен мати docstring із параметрами, типом результату, можливими помилками та side effects. Інтерфейс користується готовою `LibrarySnapshot`, не знає фізичних JSON. Service може залежати від `workspace`; Reader не залежить від GUI, `main.py`, SQLite та вмісту приватного repo. Діагностика статусу без виводу повного вмісту чужого документа у журнали.

## 6. Захист від регресій — вхідні критерії

1. Програма запускається без встановленого пакета; старі накази, інструктажі, документи й сортування тахографа працюють як до r6.
2. Клацання «Бібліотека шаблонів» відкриває тільки своє вікно; X/«Закрити», повторне відкриття і зміна фокусу коректні.
3. Відсутня бібліотека → не створено жодного каталогу, БД або чернетки.
4. Пакет з 1/10/500 синтетичних шаблонів → перегляд без втрат, стійкі ID, зрозуміле сортування.
5. Хибний manifest, SHA-256, symlink, traversal → повідомлення `DAMAGED` без читання поза root.
6. Тимчасово відсутня мережа/папка → `UNAVAILABLE` із можливістю повернення без зміни кореня workspace.
7. Window close під час refresh → немає помилок Tk, витоків потоків чи повторних вікон.
8. `main.py` збільшується тільки на мінімальний інтеграційний виклик; правило перевіряється окремим source regression.
9. Прямого запису в `Data/PaperDocuments`, `DocumentVault`, `operations_orders` немає.
10. START + повна регресія + Windows/Win7/macOS CI на одному source head; наступний реліз не називати Stable без рішення власника.

## 7. Окремі питання безпеки та формату, виявлені після r5

r5 reader робить цільову ручну перевірку частини `template_import_schema_v1.json`, але **не є повноцінним JSON-Schema валідатором**; цей факт не приховувати. Перед дозволом імпорту/використання для видачі документів окремо перевірити невідомі поля, вкладені ресурси/додатки, типи, довжини, дублікати, обмеження схеми й несуперечність `manifest.items` ↔ файли. Поточне `AVAILABLE` означає лише успішну перевірку наявним читачем, **не** юридичну чинність чи довіреність джерела.

**Виявлений крайовий випадок:** reader перевіряє заявлені файли, але не повинен автоматично довіряти стороннім неописаним файлам, що лежать поруч; майбутній інсталятор має заперечувати чужі файли всередині пакета. Обмеження каталогів, розміру/кількості ресурсів і умови `visible_when` — окреме посилення до реального випуску документів.

Не переносити ці безпекові виправлення на вже видану r5 branch під тим самим номером після її видачі користувачу. Розбирати їх малими незалежними тестованими кроками у наступних ревізіях.

## 8. Не плутати з архівом

Вікно **«Бібліотека шаблонів»** показує форми, з яких *можна буде* створити документи. Наявне вікно **«Документи»** — вже створені документи та накази. Не включати шаблони в каталог підготовлених наказів, не позначати шаблон підписаним і не створювати другий реєстр наказів.

## 9. Перед початком r6

1. Перевірити, що GitHub Pre-release `v10.18-r5` **існує**, source-tag відповідає `7ee89f3f0dcb731c4b2fd416b6ddb630e3ebe7d2`, усі релізні файли й SHA256 на місці, Stable `v10.18-r3` незмінна.
2. Звірити [PR #396](https://github.com/RomanZavadaM/Taxo/pull/396), [PR #395](https://github.com/RomanZavadaM/Taxo/pull/395), `HANDOFF_CURRENT.md`, `PROJECT_STATE.md`, release CI.
3. Створити **тільки нову** `work/v10.18-r6-...` від exact r5 head, не від `main`. Залишити r5 branch і tag незмінними.
4. Почати з regression-тестів сервісу, потім thin UI adapter, потім source/Windows/Win7/macOS verification. Не створювати інсталятора бібліотеки «заодно».
