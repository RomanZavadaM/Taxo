# Формат пакета бібліотеки шаблонів Taxo v1

**Дата:** 13.11.2026 · **Статус:** проєктний формат, не інсталятор і не робочий реліз.  
**Нормативний файл формату:** [template_catalog_manifest_v1.schema.json](template_catalog_manifest_v1.schema.json).  
**Формат одиничного шаблону:** [template_import_schema_v1.json](template_import_schema_v1.json).  
**Контракт сервісу:** [TEMPLATE_LIBRARY_INTEGRATION_CONTRACT_V1_2026-11-13.md](TEMPLATE_LIBRARY_INTEGRATION_CONTRACT_V1_2026-11-13.md).

## 1. Окремий продукт без окремої програми

Код керування й інтерфейс — у Taxo, джерельний каталог авторських матеріалів — у майбутньому **окремому приватному репозиторії**, встановлений перевірений пакет даних — у робочому сховищі Taxo за замовчуванням, або у явно вибраному каталозі. Приватний репозиторій не створено цим плануванням. Пакет **не може містити виконуваний Python, JS, скрипти, DOCM, макроси чи інструкції автооновлення/мережевого доступу**.

## 2. Структура архіву і встановленого пакета

```text
TaxoTemplates-1.0.0.zip
  manifest.json
  catalog/
    orders/
      assignment-basic.json
      assignment-temporary.json
    briefings/
      bdr-repeat-driver-quarter-01.json
      bdr-repeat-driver-quarter-02.json
    instructions/
      driver-safety-long.json
  resources/
    images/
      safety-symbols.png
    annexes/
      blank-checklist.pdf
```

**Це приклад дерева, не готовий ZIP.** Імена та матеріали лише синтетичні. Кожен шлях у маніфесті відносний, без абсолютного кореня, `..`, перехресних платформних посилань чи символічних лінків; кожен файл, крім самого manifest, має запис із `size_bytes` та `sha256`. Маніфест не містить власного SHA-256, щоб уникнути рекурсивного хешування; цілісність всього архіву перевіряється окремою контрольною сумою пакета, а автентичність видавця — окремим майбутнім механізмом. SHA-256 **не є електронним підписом**.

## 3. Маніфест: приклад форми

```json
{
  "format": "taxo.template-catalog.v1",
  "package_id": "taxo.templates.uk.general",
  "package_version": "1.0.0",
  "publisher": "Roman Zavada",
  "minimum_taxo_version": "10.18-r5",
  "language": "uk",
  "description": "Приклад каталогу: фіктивні матеріали",
  "rights": "Права на кожен матеріал мають бути підтверджені",
  "items": [
    {
      "template_id": "orders.vehicle-assignment",
      "revision_id": "rev-1",
      "category_id": "orders",
      "path": "catalog/orders/assignment-basic.json"
    }
  ],
  "files": [
    {
      "path": "catalog/orders/assignment-basic.json",
      "size_bytes": 1234,
      "sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"
    }
  ]
}
```

**ВАЖЛИВО:** `size_bytes: 1234` та `aaaa...` — демонстраційні заглушки, що мають бути замінені **реальними** значеннями збирачем пакета; такий приклад **не повинен проходити фактичну перевірку цілісності**. Формальна схема перевіряє типи полів, але **не** наявність/відповідність файлу, SHA-256, унікальність ID, межі розпакування чи можливість безпечного читання: це робота валідатора.

**Залежність від версії:** приклад `minimum_taxo_version` умовний; пакет не реалізовано, r5 не випущено. Реальна мінімальна версія буде встановлена лише після впровадження підтримки. `package_version` бібліотеки — незалежна від ревізії Taxo.

## 4. Категорії, шляхи та редакції

Початкові логічні категорії: `orders`, `briefings`, `instructions`, `training-programs`, `acts`, `forms`. Категорія — тег/вузол дерева, а не вимога до фізичної папки. Для кожного шаблону зберігається `template_id`, `revision_id`, тип документа, сценарій, назва, стан фахової перевірки, довільні структурні блоки та вкладення.

**Ідентичність:** `(package_id, template_id, revision_id)` визначає незмінний постачальний вміст; той самий ідентифікатор із **іншими байтами** у новому пакеті — конфлікт, а не тихе виправлення. Новий зміст = новий `revision_id`. Унікальність `template_id`, `(template_id, revision_id)`, `path` і відсутність неописаних файлів перевіряти окремо.

**Бібліотека підприємства:** користувацькі редакції не живуть у замінюваній vendor-папці. Рекомендація для наступної реалізації — `<workspace>/CompanyTemplates/` зі своїм індексом; зміна розміщення vendor-пакета не переносить приватні корпоративні редакції без окремого рішення.

## 5. Процедура перевірки та встановлення

1. Переконатися, що дано явно вибраний ZIP або директорію; немає мережевого auto-fetch.
2. Без розпакування прочитати центральний каталог ZIP, обмежити загальну кількість файлів, сумарний розпакований розмір, окремий файл, надмірне стиснення та вкладені архіви.
3. Відхилити абсолютні шляхи, `..`, дублікати з різним регістром на Windows, символічні лінки, невідомі типи вкладень і виконувані формати.
4. Прочитати `manifest.json` з обмеженням розміру та UTF-8, перевірити JSON Schema, відповідність версії Taxo і підтримуваного формату.
5. Звірити всі ідентифікатори/шляхи, відсутність зайвих файлів, розміри та SHA-256 кожного item/resource.
6. Перевірити кожен JSON шаблону за `template_import_schema_v1.json`, включно з типізованими змінними та забороною виконуваних виразів. Невідомі умови `visible_when` — **відхилити**, а не виконувати.
7. Скласти план змін (нові, оновлені, наявні, конфліктні), показати перед встановленням.
8. Записати в **staging** цільового workspace; звірити після запису; атомарно активувати нову vendor-версію, зберігши попередню версію для повернення.
9. Якщо щось не вдалося — не змінювати активний покажчик, не видаляти попередні vendor/company revisions. Записати зрозумілий локальний діагностичний результат без вмісту персональних документів.

**Безпека:** перевірка SHA-256 не підтверджує, що пакет «наш» або юридично правильний; перевірка джерела та цифрового підпису дистрибутива — окремий крок із явним рішенням про довіру.

## 6. Сумісність із наявною схемою окремого шаблону

Наявний `template_import_schema_v1.json` вимагає поля `format=taxo.template.v1`, `template_id`, `title`, `document_kind`, `scenario`, `language=uk`, `status=proposed`, `source_refs`, `variables` і структурні `blocks`. Пакетний manifest **не замінює** цю схему: він посилається на кожний файл конкретного шаблону. Схема одного шаблону не зобов'язана знати номер всього пакета.

Оскільки `status` чинної схеми дорівнює тільки `proposed`, юридичний/редакторський етап затвердження треба зберігати **окремими метаданими ревізії підприємства**, не змінюючи зміст `status` заднім числом.

## 7. Режим першого читача

Перший Python-модуль **тільки читає вже розпаковану папку**, без установлення ZIP, без GUI, без імпорту в SQLite, без реєстрації у `main.py`, без мережі. Мінімальні операції: визначити шлях через `workspace`; визначити стан `NOT_INSTALLED/AVAILABLE/DAMAGED/INCOMPATIBLE/UNAVAILABLE`; прочитати й перевірити manifest і всі зазначені файли; показати список категорій/шаблонів та отримати конкретну редакцію. У разі недоступності шляхів — не створювати каталог і не перезаписувати дані.

**Це окремий майбутній кодовий slice**; відбудеться на новій ревізії Taxo, з модульними тестами, повторною перевіркою Windows/Win7/macOS, лише після переходу на коректний source head (зараз r4 draft).

## 8. Редакційне наповнення і програми на 24 місяці

Перші приклади для перевірки: закріплення ТЗ, тимчасове закріплення, вступний інструктаж і 2 квартальні теми повторного інструктажу. Приклади **не містять** ПІБ, номерів реальних машин та юридично неперевірених вимог. Повну дворічну програму представляємо як окремий **затверджуваний підприємством** документ з 8 квартальними слотами, але кожна тема — власна редакція і повноцінні матеріали; при зміні програми старі факти проведення залишаються прив'язаними до старої редакції.

## 9. Межі версії 1.0

**У v1 обов'язково:** читання, перелік шаблонів, версії, цілісність, каталог, автономність від `main.py`, статус відсутності, сумісність, ручне оновлення пакетів, розділення vendor/company revisions.

**Пізніше:** повний WYSIWYG редактор, криптографічна валідація КЕП, багатокористувацькі мережеві редакції, окремий GUI-продукт та автоматичне завантаження оновлень. Дворічну ротацію в Taxo створювати окремо від читача каталогу.

## 10. Перевірки, які треба реалізувати перед прийманням

- Маніфест синтаксично правильний, але файл відсутній → `DAMAGED`.
- Маніфест із дубльованими ID/path → відмова.
- `SHA-256` не збігається → відмова.
- ZIP містить `../`, drive root, symlink, макрос чи архівну бомбу → відмова, без часткового запису.
- Файл шаблону відомого формату, але невідомий `visible_when` → відмова.
- Пакет не встановлено → Taxo запускається.
- Пакет у стандартній папці → `AVAILABLE`.
- Пакет у вибраній користувачем папці → `AVAILABLE`.
- Шлях тимчасово недоступний → `UNAVAILABLE`, без очищення конфігурації.
- Оновлення vendor не змінює company і історичні документні ревізії.
- Довгі тексти й 100+ сторінок — тест із синтетичним вмістом на окремому етапі генерації.
- Зміна SHA об'єкта старої редакції → помилка цілісності, не мовчазне прийняття.
- Повне резервне відновлення бібліотеки й корпоративних редакцій зі звіркою хешів.
