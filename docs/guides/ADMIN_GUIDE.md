# Адміністрування, робоче сховище і резервні копії — Taxo 10.x

## Робоче сховище

Taxo відокремлює програму від робочих даних. Це дозволяє оновлювати програму без повторного введення водіїв, графіків і документів.

У робочому сховищі зберігаються:
- основна SQLite-база;
- тахографічна база;
- скани;
- резервні копії;
- сформовані документи;
- копії документів транспортних засобів у `Data/VehicleDocuments`;
- архіви ревізій;
- журнали помилок/службові файли.

## Вибір місця

### Локальний диск
Найпростіший і найстабільніший варіант для одного комп’ютера.

### Мережевий SMB/NAS
Підходить для кількох робочих місць за умови почергової роботи. Taxo використовує блокування робочого сховища, щоб зменшити ризик одночасного запису.

### Синхронізована хмарна папка
Можлива, але синхронізація не є серверною базою даних. Обов’язковий порядок: закрити Taxo на першому ПК → дочекатися повної синхронізації → запускати на другому.

## Перенесення сховища

Для нового комп’ютера або другого екземпляра використовуйте **«Повна копія / перенесення…»**. Вона переносить обидві SQLite-бази, копії документів авто, тахографічні скани, шляхівки, бланки, звіти й архіви Output. Історія старих резервних копій і технічні логи не дублюються.

Перенесення виконуйте штатною функцією Taxo. Після перенесення:
1. перевірте, що нове сховище відкривається;
2. запустіть програму повторно;
3. відкрийте кілька історичних записів/документів;
4. перевірте резервну копію;
5. стару папку не видаляйте одразу — збережіть до підтвердження стабільної роботи.

## Резервні копії

Перед масовими змінами, оновленням версії, міграцією сховища або виправленням історичних даних зробіть резервну копію.

У ручній резервній копії **обидві SQLite-бази входять завжди**. Великі файлові масиви додаються окремими галочками:
- копії документів транспортних засобів;
- тахографічні скани;
- Output: шляхівки, бланки, звіти й архіви.

Самі документи та скани при цьому залишаються у робочій папці — галочки визначають лише склад конкретного backup ZIP.

Рекомендований режим експлуатації:
- робіть часті легкі backup-и баз;
- періодично створюйте backup із великими вкладеннями;
- перед перенесенням використовуйте «Повна копія / перенесення…»;
- не вважайте синхронізацію OneDrive/Dropbox повноцінною резервною копією;
- періодично перевіряйте, що резервну копію реально можна відновити.

## Відновлення

Не замінюйте активний SQLite-файл вручну під час запущеної програми. Перед відновленням:
1. закрийте всі копії Taxo;
2. зробіть копію поточного стану;
3. відновіть узгоджений набір даних;
4. запустіть Taxo й перевірте основні розділи;
5. тільки після перевірки продовжуйте роботу.

## Оновлення програми

Дані не повинні зберігатися в папці інсталяції, тому оновлення Taxo 10.x не повинно вимагати повторного введення інформації.

Перед оновленням стабільної робочої копії:
- зробіть резервну копію;
- зафіксуйте поточну версію;
- прочитайте release notes;
- спочатку перевірте оновлення на копії/тестовому робочому місці, якщо зміни значні.

## Що не слід робити

- не відкривати одну й ту саму базу двома копіями в обхід блокування;
- не редагувати SQLite вручну без контрольної процедури;
- не видаляти службові каталоги, якщо незрозуміле їх призначення;
- не змішувати робочі дані різних підприємств в одному сховищі;
- не копіювати лише один файл бази, якщо потрібно повне відновлення документів/сканів/архівів.
