# Короткий старт — Taxo 10.0

## Варіанти запуску

### Windows — встановлена версія
1. Завантажте `Taxo_v10_0_Setup_Windows_x64.exe` з GitHub Releases.
2. Встановіть програму.
3. Запустіть Taxo з ярлика.

### Windows — portable
1. Завантажте `Taxo_v10_0_Windows_x64_Portable.zip`.
2. Розпакуйте в окрему папку.
3. Запустіть `Taxo.exe`.

### Windows — перевірка через START.bat
Цей варіант призначений переважно для перевірки джерельної версії. Потрібен Python 3.13.

**Не запускайте `START.bat` прямо з відкритого ZIP.** Архіватор може тимчасово витягнути лише BAT-файл без `requirements.txt` та решти програми.

1. Завантажте актуальний START ZIP з GitHub Release.
2. Виберіть **«Видобути все / Extract all»** або в 7-Zip — **«Extract to…»**.
3. Відкрийте саме розпаковану папку.
4. Переконайтеся, що поруч із `START.bat` є `requirements.txt` і `taxo_app.py`.
5. Запустіть `START.bat`.
6. Скрипт встановить залежності з `requirements.txt` і запустить `taxo_app.py`.

У Taxo 10.0 START додатково перевіряє повноту папки. Сам BAT збережено у Windows-safe ASCII/CRLF; локалізована інструкція знаходиться в `00_README_START.txt`.

### macOS
З GitHub Releases виберіть portable ZIP для вашої архітектури: `arm64` для Apple Silicon або `x86_64` для Intel.

## Перший запуск

Під час першого налаштування визначте робоче сховище. Воно міститиме всі змінні дані програми: бази, документи, скани, резервні копії, архіви та журнали.

Рекомендовано спочатку створити окрему папку, наприклад `TaxoData`, і не змішувати її з папкою програми.

## Початкове наповнення

Перед повноцінною експлуатацією послідовно заповніть:

1. реквізити підприємства;
2. працівників і водіїв;
3. транспортні засоби;
4. маршрути;
5. серії/номери документів;
6. графік водіїв;
7. табель робочого часу.

Після цього перевірте формування одного тестового PDF для табеля/контролю та одного шляхового листа.

## Спільне сховище

Для мережевого SMB/NAS можна використовувати одне спільне сховище, але Taxo контролює почерговий доступ.

Для OneDrive/Dropbox/Google Drive: закрийте Taxo на першому комп’ютері, дочекайтесь завершення синхронізації і тільки потім запускайте на другому.

## Резервна копія перед реальною експлуатацією

Після початкового налаштування зробіть резервну копію робочої бази. Надалі резервування має бути регулярним, особливо перед масовими виправленнями або оновленням програми.
