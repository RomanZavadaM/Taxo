# Короткий старт — Taxo 10.24-r3

## Варіанти запуску

### Windows — встановлена версія
1. Завантажте **10.24-r3** з [GitHub Releases](https://github.com/RomanZavadaM/Taxo/releases/tag/v10.24-r3): `Taxo_v10_24_candidate_r3_Setup_Windows_x64.exe`.
2. Встановіть програму.
3. Запустіть Taxo з ярлика.

### Windows — portable
1. Завантажте `Taxo_v10_24_candidate_r3_Windows_x64_Portable.zip`.
2. Розпакуйте в окрему папку.
3. Запустіть `Taxo.exe`.

### Windows — перевірка через START.bat
Цей варіант призначений переважно для перевірки джерельної версії. Потрібен Python 3.13.

**Не запускайте `START.bat` прямо з відкритого ZIP.** Архіватор може тимчасово витягнути лише BAT-файл без `requirements.txt` та решти програми.

1. Завантажте [START ZIP 10.24-r3](https://github.com/RomanZavadaM/Taxo/releases/download/v10.24-r3/Taxo_v10_24_candidate_r3_START.zip) з GitHub Release.
2. Виберіть **«Видобути все / Extract all»** або в 7-Zip — **«Extract to…»**.
3. Відкрийте саме розпаковану папку.
4. Переконайтеся, що поруч із `START.bat` є `requirements.txt` і `taxo_app.py`.
5. Запустіть `START.bat`.
6. Скрипт встановить залежності з `requirements.txt` і запустить `taxo_app.py`.

У Taxo 10.x START додатково перевіряє повноту папки. Сам BAT збережено у Windows-safe ASCII/CRLF; локалізована інструкція знаходиться в `00_README_START.txt`.

### Windows 7 SP1 x64
Для підтримуваного legacy-середовища використовуйте окремий пакет з позначкою `Windows7_x64`; modern Windows package для Windows 7 не призначений.

### macOS
З GitHub Releases виберіть portable ZIP для вашої архітектури: `arm64` для Apple Silicon або `x86_64` для Intel.

## Перший запуск

Під час першого налаштування визначте робоче сховище. Воно міститиме всі змінні дані програми: бази, документи, скани, резервні копії, архіви та журнали.

Рекомендовано спочатку створити окрему папку, наприклад `TaxoData`, і не змішувати її з папкою програми.

## Початкове наповнення

Перед повноцінною експлуатацією послідовно заповніть:

1. реквізити підприємства;
2. працівників і водіїв;
3. транспортні засоби;
4. маршрути;
5. серії/номери документів;
6. графік водіїв;
7. табель робочого часу.

Після цього перевірте формування одного тестового PDF для табеля/контролю та одного шляхового листа.

## Спільне сховище

Для мережевого SMB/NAS можна використовувати одне спільне сховище, але Taxo контролює почерговий доступ.

Для OneDrive/Dropbox/Google Drive: закрийте Taxo на першому комп’ютері, дочекайтесь завершення синхронізації і тільки потім запускайте на другому.

## Резервна копія перед реальною експлуатацією

Після початкового налаштування зробіть резервну копію робочої бази. Надалі резервування має бути регулярним, особливо перед масовими виправленнями або оновленням програми.


## Накази та друк

У «Експлуатація → Накази» доступні DOCX (редагований Word), PDF та JPG, а також «Створити все». Перегляд DOCX відкриває реальну програму Word або PDF того самого наказу, якщо він уже створений. Подробиці — у [посібнику Експлуатації](OPERATIONS_STOIR_GUIDE.md). Статус і відмітка підпису не забороняють змінювати чи видаляти робочий наказ у Taxo.


## Інструктажі та стажування

У **«Експлуатація → Інструктажі та журнали»** виберіть напрям (БДР/ОП), вид, типову програму, дату і працівників. Натисніть **«Текст програми…»**, перевірте зміст і збережіть зміни. Кнопка **«Створити комплект DOCX для друку»** збереже Word-документ із програмою та окремою відомістю підписів. Відкрити його повторно можна через **«Каталог документів…»**. CSV більше не є основною дією.

Для стажування натисніть **«Експлуатація → Лист стажування…»**, виберіть стажиста, водія-інструктора і транспортний засіб, укажіть наказ, період та інші реквізити. **«Створити лист стажування DOCX»** формує редагований бланк із місцем для фактичних записів та підписів.

Нові файли лежать усередині робочого сховища `Data/PaperDocuments`, тому входять у повну резервну копію. **Друк не означає проведення, підписання чи допуску.** Опційні скани та каталог за категоріями/працівниками/ТЗ доступні у стабільній 10.24-r3.

## Перевірка після оновлення до 10.24-r3

Перед оновленням робочої копії зробіть резервну копію. Після запуску перевірте звичайний список «Документи», одну власну копію шаблону, створення контрольованої редакції Word/PDF та явне збереження готової редакції у сховище документів.

У stable 10.24-r3 перевірте також додавання, відкриття, заміну й прибирання тестового скана, позначку паперового підпису окремо від скана, дерево власних папок, регулювання області «Бланки», зміну ширини дерева каталогу та «Експлуатація → Накази → Переглянути / друк» у вузькому вікні.

## Каталог документів у стабільній 10.24-r3

- Пошук, фільтри за датою, видом, категорією, працівником, ТЗ і сканами. Сортування за датою, номером та категорією; дерево за видами/датами і власні вкладені папки. Один документ може бути у кількох папках без копіювання файла.
- Власні шаблони, контрольовані Word-редакції, PDF/друк і сховище готових документів; необов'язкові скани можна додати, відкрити, замінити чи прибрати зі збереженням історії. Скан не означає автоматично паперового підпису: його позначають окремо.
- Для документа зі сховища «Відкрити вибране» відкриває перевірену тимчасову DOCX-копію. Перед оновленням перевірте резервну копію сховища, включно з папками, історією й вкладеннями.
- Явні пари водій–ТЗ можна редагувати в наявному наказі; довгі рядки PDF-додатка переносяться в межах колонок. У шляхівках доступний календар.

У Stable 10.24-r3 доступна окрема **«Кореспонденція»**: вкладки «Вхідні»/«Вихідні», пошук, фільтр за датою з календарем, сортування, картка листа, «Новий вхідний…», «Новий вихідний…», «Відповісти…», вкладення та відкриття готового документа. Порожня дата відправлення означає лише реєстрацію, а не фактичне відправлення. Повне ручне приймання наказів і ширший захист усіх функцій ще не завершено.

**Для Test 10.24-r6:** функції кореспонденції залишаються такими самими, але їх критичні дії мають окремий live-control. Якщо кнопка відсутня, не поміщається у вікні, disabled без причини або не запускає дію, це вважається regression і має ловитися автоматичними тестами.

**Для Current Test 10.24-r9:** у «Документи ТЗ» перевірте старі протоколи/скани. «Є» тепер означає фактичну керовану копію; «Файл втрачено» означає, що в БД є посилання, але bytes недоступні. Створіть ручний backup і увімкніть **«Копії документів транспортних засобів»**: доступні legacy/source файли Taxo може зібрати в самодостатню резервну копію, а невідновлювані пропуски повинні зупинити такий backup явною помилкою. Архівований документ також має зберігати свою копію.

**Для Test 10.24-r8:** перевірте той самий наказ після повного закриття й повторного відкриття вікна: номер, дата, тема, стан, учасники, ролі/примітки та порядок мають зберегтися. Після переходу «Чернетка» → «Діє в Taxo» participant data не повинні змінитися. r7-контроль add/edit/remove, live Preview, DOCX/PDF і full backup/restore лишається чинним.

**Для Test 10.24-r4:** після вибору листа використовуйте «Отримано…» або «Надіслано…» тільки коли факт реально відбувся й відома дата. «Змінити стан…» не підміняє ці дії. «Прострочено» — лише контрольна ознака за due date, вона не закриває і не переводить лист автоматично.

**Для Test 10.24-r5:** вкладка **«Справи»** групує вже зареєстровані листи без копіювання файлів. Створіть справу → у картці листа натисніть **«Справа…»** → виберіть справу. У вкладці справ можна **«Додати пов'язані»** після перегляду/підтвердження, відкрити лист назад у журнал або вилучити його зі справи. Архівована справа не редагується до **«Відновити»**. Case membership не змінює номер, sent/received, status чи due date.
