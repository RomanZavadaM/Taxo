# Taxo 9.0 — адміністрування системи

## Що адмініструється

Для Taxo важливо розрізняти **програму** і **робочі дані**.

Програму можна перевстановити або оновити. Робочі дані повинні залишатися у вибраному робочому сховищі й не залежати від папки конкретної версії.

## Робоче сховище

За замовчуванням Taxo використовує каталог у `Documents/DriverWorktime`. Через `Файл → Робоче сховище…` можна вибрати інший корінь.

Підтримуються:

- локальний диск;
- мережева папка SMB/NAS;
- синхронізована папка OneDrive/Dropbox/Google Drive або аналогічного сервісу.

У робочому корені зберігаються змінні дані підприємства: основна та тахографічна SQLite БД, скани, вихідні документи, шляхівки, архіви, резервні копії та журнали.

## Спільна робота кількох комп’ютерів

Taxo використовує блокування робочого сховища. Це означає, що з одним сховищем одночасно повинна працювати **одна копія програми**.

### SMB/NAS

Мережевий каталог може використовуватися без ручної синхронізації, але одночасний доступ другої копії Taxo має блокуватися.

### OneDrive / Dropbox / Google Drive

Рекомендований порядок:

1. Завершити роботу в Taxo на ПК №1.
2. Дочекатися, поки служба синхронізації покаже завершення синхронізації.
3. Лише після цього запустити Taxo на ПК №2.
4. Перед поверненням на ПК №1 виконати те саме у зворотному порядку.

Не слід покладатися лише на файл блокування як на заміну завершеній хмарній синхронізації.

## Перенесення сховища

Штатне перенесення виконується через інтерфейс Taxo. Механізм використовує безпечне копіювання SQLite і перевірку БД.

Після перенесення старий каталог не слід видаляти відразу. Рекомендовано:

1. Відкрити нове сховище.
2. Перевірити водіїв, працівників, графік, табель і документи.
3. Сформувати тестовий звіт.
4. Перезапустити Taxo й переконатися, що обране сховище збереглося.
5. Зберегти старе сховище як додаткову резервну копію на визначений внутрішніми правилами строк.

## Резервні копії

Taxo створює резервні копії БД для критичних операцій і має окремий каталог `Backups` у робочому сховищі.

Рекомендовано додатково організувати зовнішнє резервування **всього робочого сховища**, а не тільки одного файла БД. Це важливо, тому що до даних належать також PDF/DOCX/JPG, скани тахокарт, архіви й журнали.

Практична схема:

- щоденна автоматична копія робочого сховища;
- окрема копія поза робочим комп’ютером;
- періодична перевірка, що копію можна відновити;
- перед великим оновленням — ручний контрольний backup.

## Оновлення програми

Перед оновленням:

1. Закрийте Taxo на всіх комп’ютерах.
2. Переконайтеся, що хмарна/мережева синхронізація завершена.
3. Зробіть резервну копію робочого сховища.
4. Зафіксуйте поточну версію.
5. Встановіть нову версію на один контрольний ПК.
6. Відкрийте існуюче сховище й перевірте основні дані.
7. Лише після перевірки оновіть інші робочі місця.

Для стабільної 9.0 не потрібно переносити БД у папку програми.

## Що не можна робити

Не рекомендується:

- запускати програму прямо з напівсинхронізованої хмарної папки, якщо в цей момент інший ПК теж працює з нею;
- вручну редагувати SQLite через сторонній редактор без резервної копії;
- замінювати одну БД старою копією, не розуміючи, які новіші документи вже створено;
- змішувати файли різних робочих сховищ;
- зберігати реальну БД у GitHub;
- розміщувати реальні персональні дані в публічних issue або release assets.

## Контроль версії

Поточна стабільна база: **Taxo 9.0**.

Для кожного релізу рекомендується перевіряти SHA-256 за файлом manifest у GitHub Release.

Під час експлуатаційного періоду нові функції не повинні автоматично ставати новою стабільною базою. Спочатку вони проходять окремий candidate/PR/CI цикл і практичну перевірку.

## Відновлення після збою

Якщо програма аварійно завершилась:

1. Не видаляйте lock-файл навмання.
2. Спробуйте повторний запуск і штатний механізм відновлення блокування.
3. Якщо БД не відкривається — не запускайте багаторазові «виправлення» сторонніми утилітами.
4. Зробіть копію поточного сховища як є.
5. Перевірте найновішу резервну копію.
6. Зафіксуйте текст помилки та журнал `Taxo_errors.log`.

Докладні сценарії: [Типові проблеми](TROUBLESHOOTING.md).
