## Обов'язковий контракт захисту

Для кожної користувацької функції має бути стабільний `function_id`, шлях від головного розділу до дії, очікуваний результат і тест. Видалення функції або заміна шляху дозволені тільки явно: рішення власника + `replaced_by` + перевірка нового шляху. Недостатньо наявності модуля, класу чи тексту кнопки.

Рівні перевірки:
1. **Реєстр** — повна інвентаризація відкритих користувачу маршрутів із власниками.
2. **Live UI** — відкрити батьківський розділ; побачити доступну активну кнопку в межах viewport; виконати дію; перевірити цільове вікно/стан. 100% маршрутів мають свій тест або явний документований виняток із датою закриття.
3. **Сценарій** — create → save → close → reopen → edit → export/preview, де застосовно; cancel/X не змінює дані; підтвердження перед руйнівною дією.
4. **Дані** — збереження історії, резервне копіювання/відновлення, скани/вкладення, cross-module routes.
5. **Візуальна доступність** — 1024×768 і 1366×768, 100/125/150% Windows; Win7/macOS в контрольних точках; усі основні дії досяжні без прихованого overflow.
6. **Негативна перевірка самого gate** — тимчасово прибрати / від'єднати елемент у тестовому середовищі та вимагати FAIL, повернути — PASS. Ці мутації ніколи не комітити у продукт.

**Правило розширення:** кожна нова user-facing кнопка/сценарій мусить бути внесена до реєстру і мати тест **в тому самому PR**, інакше CI повинен відмовити. Одного декларативного додавання ID без відповідного виконуваного тесту недостатньо.

## Поточний статус цього документа

**Оновлено 20.11.2026 після Stable 10.23-r4.** Початкова інвентаризація 19.11 лишається історичним baseline, але виконуваний реєстр уже розширено з 29 до **37 strict live routes**. Додано захист документного каталогу/дерева, зміни розміру бланків і каталогу, вибору/редагування учасників наказу, синхронізації preview та форматних дій наказу.

Це все ще **не оголошення повного захисту всього Taxo**: #556 залишається відкритим до повної інвентаризації, live-сценаріїв, даних/backup та візуальної доступності для решти функцій. Власник вручну прийняв Stable 10.23-r4; це не означає автоматичного закриття всього #556 або ширшого #553.

**Аудит 20.11.2026:** Stable r4 має 37 strict live routes. Активна r5 PR #576 додає кандидата `documents.catalog_small_viewport` і, лише після успішного merge, збільшить реєстр до 38. Старі пункти #556 про order preview / Operations / entity selection не вважати невиправленими: їх закривали r2–r4; поточний незакритий UI-slice — малий viewport каталогу документів.
