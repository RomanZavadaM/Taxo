# Аудит 10.21-r4 — сортування каталогу за датою

**Дата:** 17.11.2026  
**Issue:** #289  
**Exact product source:** `abc0d8848752b70d50f8d2d55983ed83159f24a7`

## Межа

Лише read-only порядок за датою у спільному каталозі «Документи». Натискання заголовка «Дата» змінює «новіші ▼» на «старіші ▲» і назад. При перемиканні відкривається перша сторінка. Пошук, джерело, тип, скани й період «Від / До» працюють спільно. Сортування застосовується до повної вибірки після фільтрів, до пагінації. Некоректні й порожні дати показані після датованих записів незалежно від напряму; рівні дати зберігають порядок джерела.

## Перевірки

- Нові регресії перевіряють обидва напрями, недатовані записи, спільні фільтри та сторінки, незмінність вхідного snapshot, UI перемикання, identity.
- Перший START: 1454 tests, один неправильний test expectation для рівних дат при source-specific tie-break. Виправлено лише тест. Повторний START і full exact-source — **1454/1454 PASS**.

- Windows/Win7 Defender та post-scan integrity — PASS.
- Release PR #501 merged, publisher `44127599704`: attempt 1 transient artifact egress HTTP 503 на Mac Intel, attempt 2 SUCCESS. Tag `v10.21-r4` спрямований на exact product source, 6 assets.
- Stable/Latest `v10.21-r2` не змінена.

## Не змінювалось

Дані й схема БД, DocumentVault, скани, файли, backup/restore, статуси підпису, OCR, КЕП, міграція та залежності. Інші колонки не сортувалися в r4.

## Ручна перевірка у користувача (не виконувалась у цій сесії)

У «Документи» натиснути «Дата» кілька разів, перевірити стрілки ▲/▼, першу сторінку, документи без дати в кінці та поєднання з пошуком/фільтрами. Сесія не запускала Taxo на комп'ютері власника.
