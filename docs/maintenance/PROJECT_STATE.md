# Taxo — технічний стан: stable 9.0.1 / candidate 9.1 r6

Канонічний технічний стан актуальної експлуатаційної лінії зберігається в цьому розділі. Історичний детальний стан до очищення `main` винесено в окрему гілку.

Актуальна стабільна експлуатаційна база: **Taxo 9.0.1**. Поточна гілка перевірки — **Taxo 9.1 candidate r6**. Stable 9.0.1 лишається точкою відкату до завершення експлуатаційної перевірки 9.1.

## Що змінилось у 9.0.1

- виправлено застарілий напис `v8.70 r9` у заголовку головного вікна;
- виправлено вікно **«Про програму»** — воно показує актуальну версію 9.0.1;
- START-пакет тепер формується з очищеної експлуатаційної гілки й не містить старих `CHECKPOINT_v8*`, `TEST_REPORT_v8*`, `PUBLISH_STATUS_v8*` та `PATCH_v8*`;
- дані користувача, структура SQLite і логіка розрахунків не змінюються.

## Поточний candidate 9.1 r6

Основний PR: **#29**. Лінія 9.1 додає окремий модуль «Персонал», П-5 PDF/XLSX, масове планування/відсутності, внутрішнє сумісництво та ефективно-датовані режими робочого часу.

r6:
- новий модуль `work_regime.py`;
- нова таблиця `employee_work_regimes` без перезапису існуючих даних;
- режими 5-денний / 6-денний / підсумований / індивідуальний;
- шаблони 5/40, 6/40, 6/36, 6/24;
- тижневий баланс усіх працівників за індивідуальною нормою;
- коригування норми відпусткою/лікарняним за нормою конкретного дня;
- стара масова дія «Порожні будні — план 8 год» вимкнена;
- при підсумованому обліку тижневий Δ лише довідковий;
- водійські й додаткові ролі не дублюють час і перевіряються на точний перетин.

Контрольні тести: `tests/test_v9_1_r3.py` та `tests/test_v9_1_r6.py`.

## Основні актуальні модулі

`taxo_app.py`, `main.py`, `workspace.py`, `tachograph.py`, `waybill.py`, `attestation_render.py`, `work_analysis_ext.py`, `activity_register_60.py`, `v9_release.py`, `hotfix_901.py`, `v91_features.py`, `personnel_v91.py`, `work_regime.py`.

## Відоме питання в діагностиці

В експлуатації зафіксовано Tkinter-помилку `bad window path name`. Для точного виправлення потрібен traceback із локального `Taxo_errors.log`. До отримання traceback причина не підміняється припущенням.

## Політика супроводу

Реальна експлуатація, наповнення бази, локальні виправлення відтворюваних проблем, пріоритет цілісності даних і відсутності регресій над новими функціями. Перед змінами даних — резервна копія.
