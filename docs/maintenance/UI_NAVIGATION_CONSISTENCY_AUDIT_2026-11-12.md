# Taxo — аудит узгодженості навігації та вікон (12.11.2026)

**Статус:** первинний аудит за кодом і скриншотом власника; не є підтвердженням ручного проходження всіх екранів. База — тестова 10.17-r1; робота — 10.17-r2. Документи, бібліотека шаблонів та сховище документів **поза межами змін**.

## Правила для всього інтерфейсу

1. **Головна сторінка / підсторінка у workspace:** коли внутрішні вкладки приховані, на сторінці потрібна видима команда «← До ...» із визначеним призначенням. «Закрити» — лише для окремих вікон, а не для вкладки, щоб не створювати хибне очікування закриття всієї програми.
2. **Діалог або дочірнє Toplevel:** очевидна кнопка «Закрити» або «Скасувати», коректне закриття через стандартний X; збереження — лише окремою явною дією, без неочікуваної зміни даних при виході.
3. **Таблиці:** заголовки сортуються послідовно, коректно для чисел/дат/тексту, фільтри і пошук не зникають, вибір рядка лишається визначеним після refresh. Спільний модуль існує з 10.17-r1, але застосований лише до ТЗ.
4. **Кнопки й команди:** зрозуміла назва дії, стабільне розташування первинної дії та виходу; не дублювати однакові панелі або вкладені головні меню.
5. **Вузькі екрани / DPI:** усі первинні дії досяжні без обрізання; якщо панель переповнюється — перенос або прокрутка, а не приховування.
6. **Безпека:** жодне виправлення навігації не змінює БД, накази, документи, робочий час, резервні копії та історію.

## Виявлені межі та фактичні перевірки

| Ділянка | Зафіксований стан | Рішення / наступна перевірка |
|---|---|---|
| Працівники → Планування | На скриншоті власника — «Єдине планування персоналу» без видимого повернення. Код містить прихований `personnel_book`, що пояснює пастку навігації | **Виправлено у r2**: «← До реєстру працівників», `show_personnel_overview`; перевірити вручну на Windows |
| Працівники → Табель, Звіти | Той самий прихований notebook; видимість навігаційного шляху не гарантувалася | **Виправлено у r2**: додано ту саму дію повернення; перевірити вручну |
| Працівники → Реєстр | Основний workspace; немає потреби в кнопці «Закрити» | Підтвердити зв'язок із боковим меню й повернення зі вкладених сторінок |
| Окремий детальний табель | Раніше виправлено single-instance і кнопку «Закрити» (10.1-r5) | Повторити smoke: X, Закрити, повторне відкриття, без дубльованого shell |
| Транспорт → реєстр | r1: сортування за всіма 10 колонками, збереження вибору та фільтра | Ручне приймання на реальних даних; окремо перевірити Держ. №, Рік, Документи |
| Експлуатація → Накази, Інструктажі, Стажування | Є окремі складні робочі сценарії | **Не змінювалися**. Перевірити всі Toplevel: X/Закрити/Скасувати/назад та повернення до списку |
| СТОІР / Маршрути / Тахограф | Самостійні функціональні ділянки | **Не перевірені вручну**. Інвентаризувати дочірні екрани, вихід, дублікати дій, DPI та прокрутку |
| Графіки, Табель обліку, Звіти | Вкладки, генератори файлів, вибір людей і дат | **Не перевірені вручну**. Окремо підтвердити видимість виходу, вибору і результату |
| Налаштування, службові вікна | Системні опції можуть бути модальними | **Не перевірені вручну**. Закриття без побічного збереження, досяжність кнопок |

## План наступних проходів

- **A (високий пріоритет):** вручну відкрити кожний основний пункт з лівого меню; дочірню сторінку/вікно; перевірити вихід та повторне відкриття.
- **B:** у кожному діалозі звірити «Зберегти», «Скасувати», X, Escape (якщо заявлено); жодних втрат введених даних без попередження.
- **C:** для кожної таблиці скласти перелік колонок із типами даних, пріоритет сортування та фільтрів.
- **D:** масштабування Windows 100/125/150 %, ноутбучна ширина, macOS Intel/ARM, сумісність Win7; тест CI не є заміною фізичного UI-приймання.

## Межа r2

Внести тільки явну навігацію для трьох прихованих сторінок персоналу та regression; жодних змін даних або інших workflow. Решта — **черга на перевірку, а не вже виправлені дефекти**. Це захищає від широкої одночасної зміни інтерфейсу без приймання.
