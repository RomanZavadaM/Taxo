# Перевірка заміни сканів — Taxo 10.20-r10

Дата: 17.11.2026. Issue #289, product PR #487.

## Межа зміни

Явна заміна одного активного скана паперового оригіналу у чинному DocumentVault. Попередні байти лишаються незмінними; історія отримує дію «Замінено». Нові бізнес-статуси, КЕП, автоматичний підпис, міграція, physical purge, мережеві звернення й залежності не додавались.

Реалізація залишається в окремому модулі сканів та його UI. `main.py` змінено тільки в APP_VERSION. Старі regression tests змінено тільки в очікуванні поточної версії.

## Перевірена поведінка

| Сценарій | Результат |
|---|---|
| Заміна справного активного скана | Новий ID і файл активні; попередній файл збережено, дія «Замінено» видима |
| Вибір файла скасовано / підтвердження відхилено | Жодного виклику заміни, стан не змінюється |
| Некоректний формат / повтор тих самих байтів | Відмова; попередній скан активний |
| Повторна заміна вже неактивного скана | Відмова без нового запису |
| Запис історії не вдався | Нова незавершена копія відкочується; попередній скан активний |
| Не вдались і запис історії, і відкат | Явна помилка; обидві копії збережені, попередня не втрачена |
| Пошкоджено стару копію після заміни | Перевірка цілісності виявляє пошкодження |
| Повна резервна копія та відновлення | Обидва файли, активний ID та історія «Замінено» збережені |
| Статус документа | Лишається попереднім; скан не встановлює «підписано» |
| Кнопки вікна сканів | Два ряди, доступні на 900×600 / 1024×700 / 1366×768 при звичайному й збільшеному шрифті |

Tk-перевірка реально створює вікно, викликає скасування/відмову і вимірює межі всіх кнопок. Source/Xvfb, Windows та Python 3.8 Win7 виконали її успішно; це не твердження про окреме ручне приймання власником.

## Знайдені та виправлені помилки

- Recovery знайшов уже існуючу r10 гілку `6b798332c18c1adbe2ad299020c7b06e16867b70`, якої не було в старому HANDOFF. Роботу продовжено з неї; друга реалізація не створювалась.
- Попередня r10 перевірка `44079152262` мала 35 відмов старих version guards. Завершено очікування номера, предметну логіку тестів не змінено.
- Нова Tk-перевірка на першому recovery head використала несумісний з Python 3.8 `nametofont(root=...)`. Виправлено на `Font(root=..., name=..., exists=True)`; код продукту не змінювався через цю помилку.
- Після додавання «Замінити…» ряд кнопок ставав надто довгим. Дії розміщено у два ряди й перевірено зі збільшеним шрифтом.

## Межі надійності

Заміна зберігає нову копію перед деактивацією попередньої. Раптове завершення процесу між цими кроками може залишити обидві копії активними, щоб не втратити попередній скан. Це не одна транзакція файлової системи. Звичайний збій запису покритий відкатом, важчий збій показує явну помилку та зберігає байти.

Повна ієрархія та комбіновані фільтри #289 лишаються наступними окремими кроками. Scan-filter у r10 не додано. Stable/Latest v10.20-r5 не змінюється.
