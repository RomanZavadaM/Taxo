# Taxo — поточна контрольна точка

**Stable:** Taxo 9.0.1 · 17.09.2026.  
**Current candidate:** Taxo 9.1 candidate r6 · 18.09.2026.  
**Development PR:** #29.

Stable 9.0.1 залишається експлуатаційною точкою відкату. Candidate 9.1 r6 публікується окремо як GitHub Pre-release і не оголошується stable до завершення реальної перевірки.

## Зафіксований функціонал 9.1 r6

- окремі верхні розділи **Водії** і **Персонал**;
- реєстр персоналу, ролі та внутрішнє сумісництво;
- масове планування робочих змін усіх професій;
- масові відпустки, лікарняні та інші відсутності;
- відсутність перекриває табель, але не видаляє історичний графік;
- синхронізація відсутностей зі старим табелем водія;
- П-5 у PDF та Excel з повною легендою 01–30;
- П-5 використовує графік/маршрут до появи факту;
- сформовані PDF/XLSX можна відкрити одразу;
- точний контроль перетинів ролей; тривалість без меж часу не перетворюється на вигаданий часовий інтервал;
- роль водія не дублюється через загальний employee_shifts;
- ефективно-датовані режими робочого часу;
- 5/40, 6/40, 6/36, 6/24, підсумований та індивідуальний режими;
- тижневий баланс усього персоналу: норма / коригування відсутністю / скоригована норма / план / факт / Δ;
- відпустка/лікарняний коригує норму за нормою конкретного дня, а не універсальними 8 год;
- для підсумованого обліку тижневий Δ інформаційний;
- небезпечне старе масове заповнення «8 год у кожний будень» вимкнено;
- місячний план можна створити за режимом без перезапису маршрутів, змін, ручних записів і факту.

## Дані

r6 додає таблицю `employee_work_regimes` та індекс для історії режимів. Існуючі `worklog`, `employee_time_entries`, маршрути, шляхові листи та документи не переписуються.

Робочі бази, тахокарти, скани та персональні документи не входять у GitHub-релізи.

## Релізна політика

GitHub Releases містить лише корисні контрольні точки. Завідомо дефектні проміжні кандидати не пакуються окремими релізами; їхня історія зберігається в Git/PR.

Повна історія 8.x: [history/development-v8](https://github.com/RomanZavadaM/Taxo/tree/history/development-v8).

## Продовження

Після r6 потрібна реальна експлуатація й наповнення бази. Наступні зміни робити за відтворюваними проблемами або підтвердженими експлуатаційними сценаріями.
