# Taxo 10.13-r2 — повторний UX-аудит «Експлуатації» / СТОІР

**Дата:** 07.11.2026

## Чому потрібен r2

10.13-r1 закрив функціональні розриви: профіль ТО, результат заявки, історію наказу, зрозумілий lifecycle. Повторний огляд за UX Core показав залишкову проблему: **функція є, але користувачу все ще треба здогадуватися, куди натиснути або що означає технічний код**.

## Підтверджені залишкові дефекти

1. «Стан автопарку» відкривав конкретне ТЗ тільки подвійним кліком — явної дії не було.
2. Таблиця ТО/ремонтів показувала внутрішні коди `STO` і `REPAIR`.
3. Таблиця пробігу показувала внутрішні `source_type`, наприклад `waybill_end`.
4. Дати/час у частині таблиць показувалися сирим ISO-рядком.
5. Реєстр наказів мав сім дій в один горизонтальний ряд, що суперечить мінімальному UI-gate 940×600 / збільшеним шрифтам.
6. Робочий стіл наказів мав реєстр і каталог, але не мав однієї очевидної дії «Оформити новий наказ…».
7. «Найчастіші дії» каталогу наказів теж будувалися одним довгим рядком.

## Рішення

- presentation-only humanization технічних значень;
- явна primary action для вибраного ТЗ;
- прямий start action для нового наказу;
- toolbar наказів → 3-колонкова адаптивна сітка;
- quick order actions → 2-колонкова сітка;
- старі маршрути, подвійний клік і бізнес-логіка збережені.

## Критерій готовності

- усі дії реєстру наказів видимі на мінімальній ширині;
- користувач відкриває вибране ТЗ без знання про double-click;
- у робочих таблицях немає не пояснених `STO`, `REPAIR`, `waybill_end`;
- Windows / Win7 / macOS / START gates PASS;
- жодних змін робочих даних або схеми.
