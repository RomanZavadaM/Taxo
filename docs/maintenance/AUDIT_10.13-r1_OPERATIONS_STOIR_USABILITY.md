# Taxo 10.13-r1 — аудит зручності «Експлуатації» та СТОІР

**Дата:** 07.11.2026  
**Підстава:** ручний огляд власника: «Експлуатація» і СТОІР виглядають рвано, до наказів незрозуміло, з чого починати.

## Що перевірено

Повторно прочитано чинну dev-strategy, попередні аудити 10.7/10.8/10.9, актуальні runtime-модулі та тести. Перевірка виконувалася не за критерієм «код існує», а за повним робочим маршрутом користувача.

## Підтверджені розриви

### СТОІР

1. Модель підтримувала індивідуальний профіль ТО для конкретного ТЗ, але UI не давав його налаштувати.
2. Подія ТО/ремонту зберігала виконавця й примітку, але форма їх не запитувала.
3. Заявка на несправність мала поле результату, але кнопка «Закрити» закривала запис без введення результату.
4. Пріоритети показувалися технічними значеннями `low/normal/high/critical`.
5. Зведення по автопарку було другорядною вкладкою без переходу до вибраного ТЗ.
6. Статуси прогнозу частково показували внутрішні значення `unknown/overdue/due_soon/ok`.
7. ОТК посилався на «Документи ТЗ», але прямого переходу не було.

### Експлуатація / накази

1. Користувач потрапляв у реєстр або каталог типів замість простого питання «що потрібно оформити?».
2. Внутрішня дія називалася «Затвердити», хоча фактично вона вводить структуровані дані наказу в дію в Taxo і не замінює паперове підписання.
3. Актуальний домен 10.9-r8 робить чинні/підписані накази незмінними, але UI дозволяв почати редагування і показував помилку лише при збереженні.
4. Позначка паперового оригіналу в UI виглядала як перемикач, хоча актуальна модель робить її незворотною.
5. Домен має журнал змін `order_history()`, але в UI немає нормального перегляду історії.
6. Домен має скасування, але безпечний сценарій для користувача не пояснений. У r1 скасування в UI обмежується лише чернеткою; чинний наказ змінюється новим наказом, а не заднім числом.

## Рішення 10.13-r1

### Робочий стіл «Експлуатації»

Перша вкладка «Документи» перетворюється на робочий стіл з прямим входом до:
- шляхівок;
- СТОІР / стану автопарку;
- документів ТЗ;
- військово-транспортної відомості;
- реєстру працівників;
- наказів, закріплень, відповідальних і каталогу.

Старі входи не видаляються.

### СТОІР

Робочий порядок:
**стан автопарку → вибір ТЗ → профіль ТО → факт ТО/ремонту → заявка → робота → закриття з результатом**.

Додано:
- «Стан автопарку» як першу вкладку;
- подвійний клік по ТЗ із переходом до його огляду;
- UI налаштування профілю ТО;
- виконавця й примітку у факті ТО/ремонту;
- українські пріоритети й статуси;
- окремі дії «Взяти в роботу…» та «Закрити з результатом…»;
- вимогу результату перед закриттям заявки;
- прямий перехід з ОТК до документів ТЗ.

### Накази

Робочий порядок:
**що потрібно оформити → чернетка → перевірка → ввести в дію в Taxo → паперовий оригінал → історія / новий наказ для змін**.

У UI:
- старт через «Що потрібно оформити?» з найчастішими діями;
- «Ввести в дію в Taxo» замість неоднозначного «Затвердити»;
- явне пояснення, що це не юридичний підпис;
- ранній захист від редагування чинного/підписаного/скасованого наказу;
- незворотна зрозуміла дія про підписаний паперовий оригінал;
- перегляд історії;
- скасування лише чернетки.

## Що НЕ змінюється

- plan/fact;
- схема робочої БД;
- історичні записи ТО, заявок, наказів і закріплень;
- нормативний зміст типових текстів наказів;
- release/build/CI policy;
- логіка 10.9-r8 щодо незмінності чинних наказів.

## Приймання

1. «Експлуатація» відкривається як зрозумілий робочий стіл.
2. СТОІР дозволяє пройти повний цикл без технічних назв і прихованих полів.
3. Заявку не можна закрити без результату.
4. Профіль ТО конкретного ТЗ реально редагується через UI.
5. Чинний/підписаний наказ не пропонується редагувати як чернетку.
6. Історія наказу доступна користувачу.
7. Старі маршрути залишаються доступними.
8. Windows / Win7 / macOS / START gates — PASS перед інтеграцією.
