# AUDIT — поступова модульність `main.py` — Taxo 10.8-r6

**Дата:** 30.09.2026  
**База:** immutable `v10.8-r5` / `fc9be91a892ae8be14b04c27b386da120061ec38`.

## Чому це потрібно

`main.py` історично виріс у моноліт: файл має понад 15 000 рядків і одночасно містить запуск, UI, роботу з файлами, частину схеми/БД, звіти та багато прикладних сценаріїв. Сам розмір не є runtime-помилкою, але він підвищує ризик випадкових регресій, конфліктів при змінах і складність тестування.

Рішення — **не переписувати програму одним великим кроком**. Розділення виконується тільки малими ревізіями з compatibility-wrapper там, де історичні виклики очікують ім'я з `main`.

## Перший slice r6

З `main.py` винесено нейтральну інфраструктуру роботи з вихідними файлами у `output_files.py`:

- відкриття файла/папки системною програмою;
- список системних шрифтів для PDF;
- класифікація file-access / locked-file помилок;
- підбір читабельної унікальної назви копії;
- діалог `Повторити / Створити копію / Скасувати`;
- формування дружнього повідомлення про файлову помилку;
- спільний writer-loop для PDF/XLSX та інших вихідних файлів.

У `main.py` залишений тонкий compatibility-wrapper `write_output_file()`, щоб не переписувати всі існуючі виклики одним ризиковим commit.

## Що принципово не змінюється

- жодна бізнес-модель;
- жодна таблиця робочої БД;
- plan/fact;
- Бланки підтвердження діяльності;
- роль водія;
- СТОІР;
- шляхи робочого сховища;
- правила імена вихідних файлів для користувача.

## Regression guard

`tests/test_v10_8_r6.py` перевіряє:

- current identity `10.8-r6`;
- extracted helpers більше не мають власної реалізації у `main.py`;
- історичні compatibility-імена у `main` доступні;
- `PermissionError` лишається file-access помилкою;
- ім'я копії лишається читабельним і не використовує `(1)`.

## Наступні кандидати на винесення

Робити **окремими майбутніми ревізіями**, а не все в r6:

1. backup / migration helpers;
2. attestation query/filter helpers;
3. report/export infrastructure;
4. окремі великі UI workspace-блоки;
5. DB schema/bootstrap — тільки після окремого аудиту залежностей.

Правило: один зрозумілий домен за ревізію, повний regression після кожного кроку. Не дробити `main.py` механічно заради кількості файлів.
