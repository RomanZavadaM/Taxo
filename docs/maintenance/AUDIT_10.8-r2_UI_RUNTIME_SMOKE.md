# Аудит 10.8-r2 — runtime UI smoke gate

Дата: 30.09.2026

## Мета

Після регресії, коли функція документів ТЗ залишалася реалізованою, але її точка входу зникла з інтерфейсу, статичних перевірок коду недостатньо. Потрібен тест, який створює реальні Tk/ttk-віджети та перевіряє їхню видимість і виклик команд.

## Реалізація

- CI встановлює `python3-tk` та `xvfb`.
- Повна regression suite запускається через `xvfb-run`.
- `tests/test_v10_8_r2.py` відтворює історичну умову: старий контейнер уже містить `pack`-кнопки реєстру/ТЦК, після чого встановлюється виправлена панель основних дій ТЗ.
- Тест перевіряє реальне `winfo_ismapped()` для кожної критичної кнопки.
- Кожна кнопка викликається через `.invoke()`; перевіряється маршрутизація до початкового callback.
- Окремо перевіряється вузьке вікно: усі дії лишаються видимими після переносу на кілька рядків.

## Контракт

Критичні назви згруповані у `v1082_features.CRITICAL_UI_CONTRACT`. Це дає постійний список функцій, які подальші UI-шари не мають права непомітно приховати.

## Результат

Перший Xvfb-прогін підтвердив, що всі нові runtime-тести проходять. Єдиний збій був не UI-дефектом, а старим тестом 10.8-r1, який вимагав, щоб поточний `VERSION.txt` назавжди лишався `10.8-r1`. Його переведено у коректний режим історичного regression anchor: модуль r1 зберігає власну ідентичність, а поточна версія може законно рухатися вперед.

Бізнес-логіка та схема даних не змінювались.
