# Аудит data-access foundation — Taxo 10.9-r1

## Мета

Після виділення `database_runtime.py` у 10.8-r10 наступний крок — дати новим модулям вузький і стабільний доступ до даних без імпорту великого `main.py` та без прив'язки репозиторіїв до конкретного шляху робочого простору.

## Що зроблено

- додано `data_access.py` як інфраструктурний, доменно-нейтральний шар;
- `DataAccess` працює через передану фабрику з'єднань і відкриває свіже з'єднання для кожної операції;
- додано `fetch_one`, `fetch_all`, `execute`, `executemany` та явну transaction boundary;
- успішні записи комітяться, помилки виконують rollback;
- `WorkspaceServices.connect_main_db()` тепер використовує єдину політику `database_runtime.connect_database()`;
- `ApplicationServices` надає `data: DataAccess`, тому нові feature/domain modules можуть залежати від вузького сервісного контракту, а не від `main`;
- runtime workspace path не кешується: після перемикання робочого простору наступна операція отримує новий актуальний DB path.

## Межі зміни

Ця ревізія НЕ переносить існуючі предметні SQL-запити масово і НЕ змінює таблиці, схему, міграції, бізнес-правила чи UI. Старі модулі продовжують працювати за сумісним контрактом. Новий шар є основою для поступового введення repository/service boundaries у наступних ревізіях.

## Архітектурне правило для розширення

Новий функціонал бажано будувати в напрямку:

`domain -> service -> repository/data access -> infrastructure`

UI має викликати service/domain API, а не розростатися прямими SQL-запитами. Історичний код переводиться на цю модель поступово, по одному цілісному домену, після регресійної перевірки.

## Ризики та контроль

- ризик прихованої прив'язки до старого workspace зменшено завдяки connection factory;
- транзакції не приховуються всередині domain code: для багатоопераційного запису є явний `transaction()`;
- `data_access.py` не імпортує Tk/UI або предметні модулі;
- START/source-package guards повинні включати `backup_migration.py`, `database_runtime.py` та `data_access.py`.

## Висновок

10.9-r1 закладає невелику, але важливу основу для подальшого масштабування Taxo без перетворення `main.py` та feature layers на новий моноліт залежностей.
