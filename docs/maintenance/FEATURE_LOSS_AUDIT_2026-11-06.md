# Taxo — Feature Loss Audit

Дата: 06.11.2026
База порівняння: `v10.10-r5` → current `main` (`10.12-r1` після PR #202).
Мета: знайти функції, які залишились у коді, але втратили або можуть втратити реальний користувацький маршрут.

## Ключовий критерій

Функція не вважається збереженою лише тому, що її метод/модуль існує або бізнес-тест проходить. Вона збережена тільки коли є перевірений маршрут:

`main navigation → visible action → callback → window/dialog → primary action`.

## Підтверджені втрати / історичні регресії

### 1. Простий місячний графік працівників — підтверджена поточна втрата UI-входу

- Додано в 10.10-r8; у 10.11-r2 окремо правились назви файлів і PDF.
- Код вибору працівників, шаблонів, PDF/XLSX залишався живим.
- Вхід додавався runtime-пошуком кнопки `Робочі зміни персоналу — масово…` за точним текстом.
- Власник фактично виявив, що кнопка зникла з `Працівники → Планування`.
- PR #202 / 10.12-r1 повернув постійний штатний вхід у `personnel_v91.py`; legacy injector лишено тільки fallback.

Статус: **CONFIRMED LOSS → FIXED IN 10.12-r1**, але потрібен справжній runtime reachability smoke.

### 2. Транспорт — історична UI-регресія 10.8-r1

- Основні дії ТЗ лишались у коді, але зникали через конфлікт `pack/grid` після накладання feature layers.
- Було втрачено видимість `Нове авто`, `Редагувати`, `Документи ТЗ`, `Контроль документів`, `Вивести з експлуатації`, `Оновити`.
- 10.8-r1/r2 винесли їх у власну панель і додали єдиний реальний Xvfb runtime smoke з `winfo_ismapped()` + `.invoke()`.

Статус: **HISTORICAL LOSS → FIXED AND RUNTIME-GUARDED**.

## Високий ризик тихої втрати в поточному коді

### Personnel Data Center — `Дані / Дія / документи…`

- Дія не є штатною кнопкою базового Personnel UI.
- `personnel_data_center_r6.py` обходить дерево віджетів, шукає `Новий працівник` за точним текстом і тільки тоді додає кнопку.
- Якщо anchor зміниться/переміститься, функція мовчки не встановиться.
- r6 tests перевіряють bulk/data behavior, але не runtime reachability.

Статус: **HIGH RISK**.

### Контроль обов'язкових документів працівників

- Метод `open_required_employee_documents_r7` існує.
- Основний UI-вхід створюється всередині Personnel Data Center.
- Отже втрата Data Center каскадно ховає контроль документів.
- r7 tests перевіряють правила документів/backup, але не досяжність екрана.

Статус: **CASCADE HIGH RISK**.

### Експлуатація

- Пункт лівого меню додається runtime-шаром `v1072_features.py` перед anchor `Маршрути`.
- `Експлуатація` входить до `CRITICAL_NAV_SECTIONS`, але чинний тест перевіряє лише наявність тексту у source, не `winfo_ismapped()`/invoke.

Статус: **RISK — STATIC CONTRACT ONLY**.

### СТОІР

- Пункт лівого меню додається runtime-шаром `v1084_features.py` після `Експлуатація` або `Маршрути`.
- `СТОІР` взагалі не входить до `CRITICAL_NAV_SECTIONS`.
- В tests немає `СТОІР`, `open_vehicle_maintenance` або runtime visibility smoke.

Статус: **HIGH RISK / CONTRACT GAP**.

### Військово-транспортний облік

- Кнопка додається runtime через пошук `Дані «Шлях»` або `Контроль документів`.
- Integration tests перевіряють розділення предметної логіки, але не реальну видимість кнопки.

Статус: **RISK — NO REACHABILITY SMOKE**.

### Відомість військово-транспортного обліку (додаток 1)

- Вхід додається лише після відкриття військово-транспортного dashboard.
- Код шукає кнопку `Зафіксувати подання` і вставляє поруч `Відомість (додаток 1)`.
- Немає runtime visibility/invoke test.

Статус: **NESTED RISK**.

### Центр документів / вкладка `Документи` всередині `Експлуатації`

- `DOCUMENT_CENTER_GROUPS` має статичний контракт і тести груп/методів.
- Вкладка монтується wrapper-ом поверх `open_operations_center`.
- Немає end-to-end smoke: `Експлуатація → Документи → конкретна дія`.

Статус: **MEDIUM RISK — STATIC CONTRACT ONLY**.

### Дні народження працівників

- Дія додається старим runtime anchor до `Новий працівник`.
- Наразі anchor існує, але reachability smoke немає.

Статус: **MEDIUM RISK**.

## Навмисно замінені, не вважати втратами

- Старі окремі Personnel-кнопки `Військовий облік 2026`, `Реєстр документів`, `Оригінал держреєстру`, `Військові дані / Дія`, `Звіряння через Дію` навмисно консолідовані у `Дані / Дія / документи…`.
- `PDF звіт — весь персонал` + `Excel звіт — весь персонал` у 10.11-r10 навмисно замінені selector-ом `PDF — для друку / Excel — для редагування` + `Зберегти…`.
- Старі окремі кнопки водійського PDF/деталізації у 10.11-r1 навмисно замінені `Документ:` + `Переглянути` / `Зберегти…`.

## Перевірено як збережене

- `Водії для звіту…` + вибір документу + `Переглянути` / `Зберегти…` є прямо у current `main.py`.
- `План → факт` лишився у табелі; behavioral safety r3 збережена.
- Backup `Data/EmployeeDocuments` disclosure / `core_with_employee_documents` збережений і тестується.
- Захист історії контрольних протоколів тахографа збережений DB/UI guard-ами.
- Core vehicle toolbar має найсильніший наявний runtime UI smoke.
- Waybill action surface має явний label-contract, але поки без mapped/invoke smoke.

## Головна системна прогалина тестів

Пошук по всьому test suite показав лише один справжній runtime UI visibility test із `winfo_ismapped()` — `tests/test_v10_8_r2.py` для vehicle core toolbar. Тобто більшість інтерфейсу перевіряється source-string/методами/бізнес-логікою, але не реальною досяжністю після composition feature layers.


## Додатковий автоматичний пошук сирітських callback-ів

Перевірено user-facing `open_*` / `show_*` методи у головних UI-модулях. Метод із одним входженням знайдено лише один:

- `show_dispatch_month_planner` — **не втрата**. Release notes 10.2-r8 прямо фіксують, що старий окремий dispatch planner навмисно прибраний, а compatibility method перенаправляє у `show_general_personnel_shift_planner()`.

Інші перевірені user-facing open/show methods мають щонайменше визначення + callback/registry route. Це не доводить видимість віджета, але не показало інших очевидних orphan functions.

## Історично ламкі поверхні, які треба включити у runtime gate

### Масове перепланування персоналу

- У 10.2-r3/r4 довелось повертати прапорець `Перепланувати: замінити існуючий ПЛАН…`, бо він був фізично перекритий довідковим текстом.
- Поточний код прапорець містить; test 10.2-r5 перевіряє source string і safety predicates, але не реальну видимість.
- Потрібен mapped smoke при мінімальному розмірі вікна.

### Шляхові листи — панель дев'яти дій

- У 10.6-r4 підтверджено, що крайні команди ставали невидимими при вузькому вікні/DPI.
- Поточний `WAYBILL_ACTION_LABELS` contract зберігає повний список, але runtime mapped/invoke smoke для всіх дев'яти дій відсутній.
- Gate має перевіряти мінімальну ширину та wrap/reflow, а не лише labels у source.

## Механічне порівняння labels після stable r5

Для runtime-файлів, змінених після `v10.10-r5`, порівняно user-facing labels старої та поточної версій. Прямого безпояснювального видалення Personnel/Tachograph actions не знайдено. В `main.py` зникли лише відомі навмисні UX-підписи:

- `PDF звіт — весь персонал` / `Excel звіт — весь персонал` → selector + `Зберегти…`;
- окремі `PDF — графік` / `PDF — деталізація` → `Документ:` + `Переглянути` / `Зберегти…`;
- старий короткий backup disclosure замінений точнішим складом backup.

Це підтверджує, що головний ризик Taxo зараз — не delete функціонального коду, а **runtime composition/layout, який робить живий код недоступним користувачу**.

## Наступний етап

1. Розширити `CRITICAL_UI_CONTRACT` до реєстру функцій/маршрутів, а не лише labels.
2. Додати `СТОІР` і всі інші dynamic navigation entries.
3. Створити headless Xvfb smoke по доменах: Personnel, Planning, Data Center, Operations/Documents, STOIR, Military Transport, Reports/Timesheet, Waybills, Tachograph, Backup/Settings.
4. Для кожного required route перевіряти mapped action + callback + відкриття потрібного window/tab.
5. Release gate має падати при `missing`, `unreachable` або `orphaned` required function.
