# Taxo — стан продукту

## Поточний статус

**Taxo 10.0 — stable.**

Паралельно підготовлено **Taxo 10.1-r1 candidate** для ручної перевірки. Він виправляє розділення статусу працівника і ролі водія та додає перший етап UI refresh. Stable 10.0 не замінено.

### 10.1-r1 candidate

- `employees.active` більше не синхронізується з `drivers.active`;
- завершена роль `Водій` не повертається після restart;
- `driver_end_date` не стирається звичайним редагуванням;
- re-employment не активує водія автоматично;
- UI отримав динамічну brand-шапку, м'яку синьо-жовту палітру та text-free sun+bus icon;
- regression gate: **126 tests / OK**.


Лінію 9.1 завершено після автоматичних перевірок і ручного operational gate на реальній Windows-базі. Останній кандидат — **v9.1-r9.8**. Попередня stable/rollback точка — **v9.0.1**.

## Що входить у 10.0

- канонічний стан дня для «Табеля» і «Графіка водіїв»;
- точні інтервали, split-shift і нічні переходи через 00:00;
- union-розрахунок перекриттів без подвійного часу;
- модуль «Персонал», режими робочого часу та відсутності;
- П-5 PDF/XLSX з явним рішенням щодо підстановки плану;
- архів підтверджень діяльності з фільтрами;
- місячний контроль і PDF деталізації;
- «Аудит графіків…» окремо від «Контролю №340»;
- шляхівки, нумерація, пробіг/спідометр та історія пробігу;
- один лікар/механік на role + date + shift, legacy-дублікати як конфлікт;
- analog tachograph workflow;
- резервні копії та переносиме робоче сховище;
- Windows-safe START.bat.

## Stable release packages

GitHub Release **v10.0** опублікований з target `91c0d6365a40eb09fe40f97a2965da40b314bc15` і містить:
- Windows x64 Setup;
- Windows x64 Portable;
- macOS ARM64 Portable;
- macOS Intel x86_64 Portable;
- START/source archive;
- per-platform і combined SHA-256 manifests.

Фінальний regression suite: **117 tests / OK** на Windows, macOS ARM64 та macOS Intel.

Релізні пакети не містять робочих БД, сканів, кешів або персональних документів.

## Дані й сумісність

- 10.0 використовує наявне робоче сховище;
- повторно вводити дані не потрібно;
- історичні worklog/work_segments не переписуються автоматично;
- відсутність не видаляє історичний план;
- перед оновленням рекомендована резервна копія.

## Аудит і контроль

**Аудит графіків** — технічна перевірка правильності часових даних.

**Контроль №340** — окрема нормативна перевірка.

Ці механізми не підміняють один одного.

## Релізна політика після 10.0

- `main` — stable 10.0;
- `v10.0` — immutable stable release;
- candidate tags `v9.1-r5` … `v9.1-r9.8` лишаються історичними;
- старі теги/releases не пересуваються і не перезаписуються;
- нові функціональні зміни знову ведуться через окрему робочу гілку/PR;
- база даних не публікується.
