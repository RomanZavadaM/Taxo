# Taxo 9.0 — експлуатація, дані та резервування

## 1. Робоче сховище

Усі змінні дані Taxo зберігаються в одному **робочому сховищі**. Воно може бути:

- локальною папкою;
- мережевою SMB/NAS папкою;
- локальною папкою, синхронізованою OneDrive/Dropbox/Google Drive.

За замовчуванням використовується `Documents/DriverWorktime`, якщо користувач не вибрав інше сховище.

У сховищі знаходяться БД, скани, вихідні документи, резервні копії та журнали. Тому переносити систему потрібно як єдине сховище, а не як окремий файл БД.

## 2. Одночасна робота

Taxo використовує файл блокування робочого сховища. Практичне правило: **одне сховище — одна активна копія Taxo**.

Для мережевої папки відкривайте наступну копію тільки після закриття попередньої.

Для хмарної синхронізації:

1. закрийте Taxo на першому комп'ютері;
2. дочекайтесь завершення синхронізації папки;
3. переконайтесь, що синхронізація завершилась на другому комп'ютері;
4. лише після цього запускайте Taxo там.

## 3. Резервні копії

Taxo створює узгоджені SQLite-резервні копії у робочому сховищі.

Рекомендації:

- не покладатися тільки на одну локальну копію диска;
- періодично перевіряти наявність свіжих backup-файлів;
- мати додаткову зовнішню копію всього робочого сховища;
- перед великим оновленням або перенесенням створювати окремий backup;
- періодично тестувати відновлення на копії, а не лише факт наявності ZIP/DB.

## 4. Перенесення сховища

Використовуйте штатну функцію `Файл → Робоче сховище…`.

Безпечне перенесення виконує копіювання БД через SQLite backup, переносить інші файли й перевіряє цілісність. Старе сховище не слід відразу видаляти — залиште його до підтвердження нормальної роботи нового.

## 5. Оновлення програми

Робочі дані відокремлені від файлів програми, тому нову версію можна встановлювати без перенесення БД у каталог програми.

Перед оновленням:

1. закрийте Taxo на всіх комп'ютерах;
2. переконайтесь у наявності резервної копії;
3. збережіть інформацію про поточну версію;
4. встановіть нову версію або розпакуйте Portable;
5. запустіть і перевірте правильне робоче сховище;
6. зробіть короткий smoke-test: працівники, табель, маршрут, ТАХО, PDF, шляхівка.

Не копіюйте БД у папку нової версії програми.

## 6. Релізи і контрольні суми

Стабільні релізи публікуються на GitHub Releases. Для v9.0 доступні пакети Windows/macOS та `SHA256SUMS_v9_0.txt`.

Для контрольованого встановлення рекомендується звіряти SHA-256 завантаженого файла з маніфестом релізу.

## 7. Журнали помилок

Технічні помилки записуються у каталог журналів робочого сховища. При зверненні щодо дефекту корисно передавати:

- версію програми;
- точні кроки відтворення;
- скриншот;
- дату/водія/документ без зайвого розголошення персональних даних;
- відповідний фрагмент журналу помилок.

## 8. Збереження даних

Проєктна вимога Taxo — зберігати історію водіїв і робочого часу щонайменше **48 місяців**. Для тахокарт у поточній експлуатаційній моделі використовується 60-денний робочий реєстр діяльності, але самі історичні дані системи не потрібно видаляти через 60 днів.

## 9. Що не входить у GitHub

У репозиторій і релізи не повинні потрапляти:

- `.db`, `.sqlite`, `.sqlite3` робочих БД;
- скани реальних тахокарт;
- персональні реєстри підприємства;
- сформовані робочі документи з персональними даними;
- резервні копії робочого сховища.

CI релізів перевіряє відсутність БД у пакетах.

## 10. Мінімальний щомісячний контроль адміністратора

- перевірити версію Taxo;
- перевірити, що backup оновлюється;
- перевірити вільне місце на диску/хмарі;
- переконатися, що Output/Scans/Backups доступні;
- переглянути журнал помилок;
- вибірково відкрити старий PDF і старий запис табеля;
- перевірити, що спільне сховище не використовується паралельно.
