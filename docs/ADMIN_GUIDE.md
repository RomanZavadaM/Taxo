# Адміністрування Taxo 9.0

## 1. Версія для експлуатації

Базова стабільна версія — **Taxo 9.0**. Для штатної роботи використовуйте пакети з офіційного GitHub Release `v9.0` або новішого підтвердженого релізу.

Не замінюйте робочу версію випадковим архівом із гілки розробки.

## 2. Варіанти запуску

### Windows Setup

Рекомендований варіант для звичайного робочого місця. Програма встановлюється окремо від робочих даних.

### Windows Portable

Можна використовувати без інсталяції. Робоче сховище все одно повинно бути окремим від каталогу програми.

### macOS

Використовуйте пакет відповідної архітектури: Apple Silicon `arm64` або Intel `x86_64`.

### START.zip

Призначений для перевірки змін та запуску з Python 3.13. Для звичайного персоналу краще використовувати готову збірку.

## 3. Робоче сховище

Taxo зберігає змінні дані в окремому робочому корені. За замовчуванням це `Documents/DriverWorktime`.

У сховищі знаходяться:

- основна SQLite-база;
- база/дані модуля тахографа;
- тахографічні скани;
- резервні копії;
- PDF/Excel та інші вихідні документи;
- архіви шляхових листів і підтверджень;
- журнали помилок.

## 4. Перенесення сховища

Використовуйте штатну функцію `Файл → Робоче сховище…`. Не переносіть активну базу вручну під час роботи програми.

Перед перенесенням:

1. закрийте всі інші копії Taxo;
2. переконайтесь, що цільова папка доступна для читання і запису;
3. зробіть резервну копію;
4. виконайте перенесення штатною функцією;
5. після завершення перевірте запуск, водіїв, табель, шляхівки та тахографічний каталог.

Стара папка після штатного перенесення не повинна видалятись автоматично; зберігайте її до перевірки нового місця.

## 5. Спільна робота

### SMB/NAS

Кілька комп'ютерів можуть бути налаштовані на одне сховище, але Taxo має використовуватись послідовно. Вбудоване блокування не дозволяє штатний одночасний запис кількох копій.

### OneDrive / Dropbox / Google Drive

Порядок роботи:

1. закрити Taxo на першому комп'ютері;
2. дочекатись завершення синхронізації;
3. переконатись, що на другому ПК синхронізація завершилась;
4. тільки після цього запускати Taxo на другому ПК.

Не використовуйте режим, коли дві копії працюють одночасно і сподіваються, що хмарний сервіс «склеїть» SQLite-базу.

## 6. Оновлення програми

Перед оновленням:

1. закрийте Taxo;
2. зробіть/перевірте резервну копію робочого сховища;
3. зафіксуйте поточну версію;
4. встановіть або розпакуйте нову версію окремо;
5. запустіть її на тому самому робочому сховищі;
6. перевірте основні довідники та один типовий робочий сценарій.

Базу не потрібно копіювати в каталог нової версії.

## 7. Відновлення після аварійного завершення

Якщо програма завершилась аварійно і залишилось блокування сховища, спочатку переконайтесь, що Taxo реально ніде не запущений. Лише після цього використовуйте штатну процедуру відновлення доступу.

Не видаляйте службовий lock-файл навмання, якщо не перевірено інші робочі місця.

## 8. Доступ до файлів

Робоча папка повинна мати права читання/запису для користувача Taxo. Антивірус, резервне ПЗ або хмарний клієнт не повинні блокувати SQLite-файли на тривалий час.

## 9. Журнали помилок

Технічні помилки записуються в каталог `Logs` робочого сховища. При зверненні з проблемою корисно зберегти відповідний журнал разом зі скриншотом і описом дій.

## 10. Мінімальний контроль адміністратора

Регулярно перевіряйте:

- чи створюються резервні копії;
- чи є вільне місце на диску;
- чи синхронізується спільна папка без конфліктних копій;
- чи не запускаються застарілі версії Taxo;
- чи відкриваються останні сформовані PDF;
- чи немає постійних помилок у `Logs`.

Детальніше про резервні копії: [BACKUP_AND_RECOVERY.md](BACKUP_AND_RECOVERY.md).
