# Taxo 10.7-r4 — candidate release notes

**Статус:** candidate / fast-test, не stable.  
**Дата підготовки:** 29.09.2026.  
**Stable line не змінюється:** `v10.3`.

## Основна тема

Виправлення робочого процесу наказів у розділі **«Експлуатація»**: редагування без втрати простежуваності, журнал змін, робота з підписаним паперовим оригіналом, корекція закріплень ТЗ/водіїв і додатків.

## Що змінено

- Накази можна коригувати після створення незалежно від внутрішнього стану `Чернетка / Затверджено / Скасовано`.
- Внутрішній статус більше не використовується як технічний lock робочих даних.
- Додано ознаку **«паперовий оригінал підписано»** з датою фіксації.
- Після редагування запису, для якого паперовий оригінал уже позначено підписаним, Taxo попереджає про необхідність звірити документ і за потреби передрукувати/підписати повторно.
- Додано `operations_change_log` для історії створення, редагування, затвердження, скасування, зміни паперового статусу, закріплень і додатків.
- Рядки **ТЗ / водій** можна додавати, редагувати та прибирати; корекції протоколюються.
- Є прямий сценарій **«Створити наказ про закріплення»**.
- Додатки до наказів можна коригувати після внутрішнього затвердження; create/update/delete пишуться у change log.
- Міграції з r2/r3 additive: існуючі записи не видаляються і не переписуються масово.
- Прибрано дублюючий зовнішній UI-patch: єдиним робочим інтерфейсом `Експлуатація` є `operations_orders_ui.py`.
- UI редагування наказів використовує модельний API `ops.update_order(...)`, а не прямий SQL, тому зміни не обходять журнал історії.

## Regression / packaging safeguards

- Додано `tests/test_v10_7_r4.py` для:
  - редагування затвердженого наказу;
  - збереження історії;
  - корекції після позначки підписаного паперового оригіналу;
  - редагування закріплення;
  - additive migration r2/r3 → r4;
  - корекції затвердженого додатка з history log;
  - ідентичності `10.7-r4`.
- START-package guard тепер обов'язково перевіряє наявність `v1074_features.py` і `v1074_appendix_history.py`.
- Робочі БД, персональні документи, скани та кеші як і раніше не входять у release package.

## Важливе розмежування

Taxo зберігає робочий структурований запис та історію його змін. Позначка **«паперовий оригінал підписано»** не робить електронний запис незмінним: якщо виявлено описку або помилку, її можна виправити, але підписаний паперовий примірник після цього потрібно звірити і, якщо зміна впливає на його зміст, оформити належний актуальний примірник.
