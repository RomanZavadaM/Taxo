# Taxo 10.14-r9 — автоматичне оновлення вже відкритого перегляду наказу

**Дата:** 09.11.2026  
**Тип:** candidate / owner-found live synchronization regression fix.  
**Stable:** без змін, `v10.14-r4`.

## Що показав реальний тест

На наказі №28 дані вже зберігались правильно:

- вкладка «Закріплення водіїв» показувала `закріплень: 1`;
- у таблиці була пара MAN / держномер / Рудинець Петро.

Але відкрите раніше вікно «Перегляд наказу №28» продовжувало показувати:

`(закріплення ще не додані)`.

Отже r8 закрив збереження БД і свіжі дані перед DOCX/PDF/JPG, але не синхронізував уже відкрите Preview відразу після зміни закріплень.

## Виправлено

- кожне відкрите Preview реєструється для конкретного `order_id`;
- після додавання однієї пари Preview цього наказу оновлюється автоматично;
- після «Додати багато…» Preview оновлюється автоматично;
- після редагування пари Preview оновлюється автоматично;
- після видалення пари Preview оновлюється автоматично;
- якщо відкрито кілька Preview того самого наказу, оновлюються всі;
- закриті Preview автоматично прибираються з реєстру;
- «Оновити зміст» лишається як ручна допоміжна дія, але більше не потрібна для нормального робочого сценарію;
- у статусі Preview після синхронізації показується фактична кількість закріплень.

## Контроль

Додано 27-й critical route:

`operations.assignment_preview_sync`

Live regression повторює owner-сценарій:

1. відкрити наказ без закріплень;
2. не закривати Preview;
3. перейти у «Закріплення водіїв»;
4. «Додати одну пару»;
5. вибрати MAN + водія;
6. натиснути «Додати»;
7. те саме Preview без ручного refresh мусить прибрати «закріплення ще не додані» та показати MAN, держномер і ПІБ водія.

Цей тест працює разом із r8 persistence/outcome tests: UI синхронізація не замінює перевірку commit → DB reopen → document layout.

Stable / Latest не пересувається без окремого рішення власника.
