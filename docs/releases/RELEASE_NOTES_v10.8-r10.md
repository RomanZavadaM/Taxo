# Taxo 10.8-r10 — fast-test

**Статус:** кандидат для тестування / prerelease.  
**База:** immutable `v10.8-r9`.  
**Stable:** `v10.3` не змінюється.

## Мета ревізії

Продовжити малу безпечну декомпозицію великого `main.py`: винести низькорівневу SQLite connection policy у окремий infrastructure-модуль без зміни поведінки програми та даних користувача.

## Що змінено

- додано `database_runtime.py`;
- винесено відкриття поточної SQLite-БД та connection PRAGMA;
- збережено timeout 30 с і busy timeout 30000 мс;
- збережено `sqlite3.Row`;
- збережено `foreign_keys=ON`;
- збережено `journal_mode=DELETE`;
- збережено `synchronous=FULL`;
- `main.db()` лишився compatibility wrapper для всіх наявних call sites;
- актуальний `DB_PATH` передається при кожному відкритті, тому переключення workspace не ламається;
- `START.bat` контролює наявність `database_runtime.py`;
- додано `tests/test_v10_8_r10.py`;
- додано аудит `docs/maintenance/AUDIT_DATABASE_RUNTIME_INFRASTRUCTURE_v10.8-r10.md`.

## Що НЕ змінювалося

- схема та формат робочої SQLite-БД;
- workspace і розташування даних;
- backup/restore semantics;
- табель і plan/fact;
- Бланки підтвердження діяльності;
- роль водія;
- СТОІР;
- документи ТЗ;
- військовий облік;
- UI/UX;
- stable `v10.3`.

## Що перевірити вручну

1. Запуск на наявному робочому workspace з реальною БД.
2. Відкриття основних розділів, що читають/пишуть SQLite.
3. Переключення workspace і повторний доступ до даних.
4. Backup/restore після переключення workspace.
5. Звичайне завершення та повторний запуск програми.

## Версіювання

`10.8-r10` — остання ревізія лінійки `10.8`. Після її видачі будь-яка наступна кодова зміна повинна бути **`10.9-r1`**.

## Важливо

- це fast-test checkpoint;
- PR не зливається в `main` без окремої команди власника;
- після видачі `v10.8-r10` ревізія заморожується;
- робочі БД, документи, скани та кеші користувача до пакета не входять.
