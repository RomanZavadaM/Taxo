# Taxo 10.14-r7 — строгий контроль досяжності критичних функцій

**Дата:** 09.11.2026  
**Тип:** candidate / Feature Loss control hardening.  
**Stable:** без змін, `v10.14-r4`.

## Причина

Експлуатаційне тестування 10.14-r6 показало системну прогалину: тест міг підтвердити, що кнопка або підпис існують у дереві Tk, але не доводив, що користувач реально бачить елемент і може ним скористатись.

Так був пропущений механізм масового вибору водіїв/ТЗ: код залишався, але блок опинився за межами робочого вікна.

## Новий принцип gate

Для кожного `runtime_smoke=True` маршруту тепер обов'язковий зареєстрований live-test. Такий test не може завершитись PASS, доки для свого маршруту не зафіксує всі чотири докази:

1. `mapped` — віджет реально змонтований;
2. `onscreen` — має ненульовий розмір і фізично знаходиться у доступних межах вікна;
3. `usable` — не disabled;
4. `activation` — дія реально активується або існує перевірений інтерактивний маршрут.

Meta-gate звіряє Function Registry і реєстр live-test 1:1. Додавання нового критичного маршруту без такого тесту валить regression suite.

## Покриття

На строгий механізм переведено всі 25 поточних критичних маршрутів: Personnel/Data Center, планування, вибір водіїв для звіту, План → факт, core ТЗ, військово-транспортний облік, Експлуатація, масові закріплення, інструктажі, СТОІР, центр документів, шляхові листи, тахограф, звіти та налаштування.

Окремо додано відсутній живий контракт для вкладки «Інструктажі та журнали».

## Що це змінює

Статичний пошук тексту або callback більше не може вважатись достатнім доказом збереження критичної UI-функції. Якщо віджет існує, але схований, перекритий, винесений за межі вікна, disabled або не активується — відповідний live-test має впасти.

Бізнес-логіка, дані користувача та stable release цим кроком не змінюються.
