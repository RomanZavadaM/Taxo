# Taxo 10.14-r7 — закріплення водіїв/ТЗ у вже створеному наказі

**Дата:** 09.11.2026  
**Тип:** candidate / Feature Loss regression fix.  
**Stable:** без змін, `v10.14-r4`.

## Виявлено власником

Після r6 створення нового наказу про закріплення знову мало видимі списки ТЗ і водіїв, але при відкритті вже створеного наказу через «Редагувати наказ» цей механізм був відсутній.

Причина була прямою: блок вибору в `operations_orders_ui.py` створювався лише для нового наказу (`existing is None`). Тому тест r6 перевірив лише сценарій створення і не захистив сценарій редагування.

## Виправлено

- у «Редагувати наказ» для наказу про закріплення показується окремий блок «Водії і ТЗ цього наказу»;
- у ньому видно поточний перелік пар ТЗ / номер / водій;
- кнопка «Додати багато…» веде прямо до масового вибору для цього вже існуючого наказу;
- «Керувати закріпленнями» відкриває штатну вкладку, де можна редагувати або видаляти окремі пари;
- підписаний паперовий оригінал, статус наказу та інші службові ознаки не блокують ці робочі дії;
- виправлено накладання попередження про паперовий підпис на поле тексту наказу.

## Посилення Feature Loss Guard

Додано окремий protected route `operations.assignment_existing`.

Новий live-test проходить саме шлях:

існуючий наказ → «Редагувати наказ» → поточні закріплення видимі → «Додати багато…» видима → масовий picker відкривається → два списки ТЗ/водіїв реально доступні.

Це доповнює r6, який перевіряє створення нового наказу. Загальне meta-gate hardening лишається в Issue #275.
