# Taxo 10.18-r6 — тестова бібліотека шаблонів (перегляд)

**Статус:** окремий кандидат до тестування, **не Stable**. Кодова база: перевірений точний head `10.18-r5` `7ee89f3f0dcb731c4b2fd416b6ddb630e3ebe7d2`.

## Зміни

- Вбудований у Taxo пункт **«Шаблони → Бібліотека шаблонів…»** через чинний механізм `feature_layers.py`; без додавання бізнес-логіки в `main.py`.
- Окремі `template_library_service.py`, `template_library_ui.py`, `template_library_feature.py`; логіка перевірки цілісності залишається в `template_library_reader.py` із r5.
- Окреме дочірнє read-only вікно показує стан, шлях, версію бібліотеки, кількість шаблонів, категорії, пошук, сортування, «Оновити» і «Закрити».
- Читання виконується поза Tk main loop, кількість одночасних читачів обмежена. X закриває **лише** дочірнє вікно, не Taxo.
- Вікно бере поточний workspace із `ApplicationServices.workspace.root`. Якщо активний workspace — `C:\\Users\\roman_mmg2lw7\\Documents\\DriverWorktime\\Work`, бібліотека очікується в `Work\\TemplateLibrary`. **У коді немає жорстко зашитої особистої адреси.**
- Додані синтетичні тести відсутньої бібліотеки, відсутності побічних записів, коректності сервісної моделі, ізоляції модулів і зв'язку через feature registry.

## Приватна тестова бібліотека

Пакет **не включається в відкритий реліз Taxo**. Джерело — приватний `RomanZavadaM/transport-docs-catalog`, гілка `package/taxo-library-test-2026-11-13`, 28 знеособлених шаблонів. GitHub ZIP із цієї приватної гілки слід розпакувати у `<workspace>/TemplateLibrary/`, щоб `manifest.json` лежав у її корені. Самі реальні шаблони і тексти не потрапляють у публічний Taxo, CI або release assets.

Стан `AVAILABLE` означає проходження поточної технічної перевірки читача, а **не** юридичне затвердження чи перевірений КЕП. Не створювати/підписувати документи за цими шаблонами без юридичної і редакційної перевірки.

## Межі r6

У r6 поки **немає** редагування шаблонів, генерації готових наказів, автоматичного встановлення ZIP, зміни директорії бібліотеки через UI, синхронізації з приватним GitHub, перевірки КЕП чи роботи з архівом готових документів.

Немає змін SQLite, операцій `PaperDocuments`, `DocumentVault`, резервування чи наявних шаблонів наказів. Stable/Latest `v10.18-r3` не змінюється без рішення власника.

Опублікувати та перевірити обов'язковий GitHub Portable Pre-release `v10.18-r5` на його незмінному exact code head, після чого випускати r6 під **іншим** source head. Звірити CI START/source, Windows, Win7, macOS Intel+ARM, архіви й checksums. Ці release notes не свідчать, що r6 вже опублікований або що Windows UI прийнятий вручну.
