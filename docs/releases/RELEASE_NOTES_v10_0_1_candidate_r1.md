# Taxo 10.0.1 candidate r1

**Hotfix candidate — 19.09.2026**

Stable/rollback лишається **Taxo 10.0**. Цей кандидат виправляє розділення кадрового статусу працівника і водійської ролі.

## Виявлена проблема

У ранніх версіях Taxo всі записи каталогу `drivers` фактично вважалися водіями. Після появи загального реєстру «Персонал» startup-міграція залишилась надто агресивною.

Сценарій дефекту:
1. у картці працівника зняти роль **«Водій»**;
2. Taxo коректно питає дату завершення ролі;
3. водійська картка стає неактивною;
4. після виходу і повторного запуску:
   - `drivers.active=0` копіювався в `employees.active`, тому працівник ставав **«Звільнений»**;
   - startup-код безумовно знову додавав `employee_roles.role='Водій'`.

Додатково при наступному редагуванні працівника без ролі «Водій» могла очищатися збережена `driver_end_date`.

## Правило 10.0.1 r1

Після первинної міграції:

- **employees.active / dismissal_date** = кадровий статус працівника;
- **employee_roles** = поточні спеціальні ролі;
- **drivers.active / driver_end_date** = лише стан та історична дата завершення водійської ролі;
- завершення ролі водія **не звільняє працівника**;
- поновлення працівника **не відновлює роль водія**, якщо її було окремо завершено.

## Що виправлено

- startup bridge створює працівника для legacy driver лише якщо linked employee ще не існує;
- повторний запуск не переписує `employees.active` зі значення `drivers.active`;
- повторний запуск не відновлює роль «Водій»;
- `driver_end_date` не стирається при звичайному збереженні працівника без водійської ролі;
- «Звільнити / поновити» більше не відновлює водійську роль автоматично;
- редагування неактивної історичної картки водія не робить працівника звільненим і не додає роль, доки водій явно не активований;
- первинна міграція старих БД з каталогу drivers збережена;
- START naming підтримує patch candidate `10.0.1 candidate r1`.

## Regression tests

Додано `tests/test_v10_0_1_r1.py`:
- restart не повертає роль «Водій»;
- restart не змінює працюючого працівника на «Звільнений»;
- перша legacy-міграція все ще створює працівника-водія;
- завершення водійської ролі не змінює кадровий статус;
- наступне редагування зберігає дату завершення ролі;
- rehire працівника не відновлює завершену роль водія;
- patch candidate має правильну назву START-архіву.

## Важливо для вже зачеплених даних

Candidate **не виправляє неоднозначні кадрові записи автоматично**.

Якщо 10.0 уже встиг після перезапуску:
- поставити працівнику «Звільнений»;
- повернути роль «Водій»;

то на r1 потрібно один раз вручну:
1. відкрити картку працівника;
2. встановити **«Працює»**, якщо людина реально працює;
3. прибрати **«Водій»**;
4. вказати правильну дату завершення водійської ролі;
5. зберегти;
6. перезапустити Taxo і переконатися, що стан не змінюється.

Робоча БД, скани й персональні документи до release archive не входять.
