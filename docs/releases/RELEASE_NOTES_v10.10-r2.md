# Taxo 10.10-r2 — CI hardening та ізоляція тестів

**Дата:** 05.10.2026  
**База:** `main` після 10.10-r1 (PR #136)  
**Тип:** інфраструктурна ревізія. Код програми, схема БД і дані користувача **не змінюються**; вбудовані механізми програми (робоче сховище, автоматичні резервні копії, завершення ролі водія) не зачіпаються.

## Що змінено

### GitHub Actions
- 72 одноразові workflow історичних ревізій (`publish-*`, `apply-*`, `repair-*`, `restore-*`, `backfill-*`, `update-release-*`) перенесені в `docs/history/workflows/` і більше не виконуються.
  - Закрито ризик C1 з аудиту: `publish-v10.3.yml` і `update-release-description-v9.yml` мали `contents: write` і могли переписати історичні releases при push у `main`.
- У `.github/workflows/` лишились 4 gates, усі лише з правом читання: Windows (`build-windows`, required), Windows 7, macOS, START/Linux.
- Required check `build-windows` запускається на **всіх** pull request — PR лише з документацією більше не блокуються.
- Збірка Windows 7 запускається також на push у `main`, щоб пакети для релізу збиралися з коміту в `main`.

### Тести
- `tests/test_00_isolation.py` завантажується першим і до будь-якого імпорту `main` перенаправляє робоче сховище та теку налаштувань (`TAXO_WORKSPACE_ROOT`, `TAXO_CONFIG_DIR`) у тимчасову теку. Причина — інцидент 05.10.2026: локальний прогін регресії записав тестові записи в реальну робочу БД.
- `tests/stage_legacy_layout.py` повертає архівні workflow в `.github/workflows/` лише в робочій копії CI — історичні тести працюють без змін.
- `tests/test_v10_10_r2.py`: інвентар активних workflow (з git), заборона write-прав і release-кроків, required check на всіх PR.
- Тест ідентичності 10.10-r1 переведено на «10.10-r1 або пізніше».

### Версія
- `VERSION.txt`, `main.APP_VERSION`, `START.bat`, Inno Setup і назви артефактів — **10.10-r2**.

## Правило

Регресійні тести запускаються **лише в CI** або в ізольованому середовищі; ніколи — на машині з реальним робочим сховищем без згоди власника.
