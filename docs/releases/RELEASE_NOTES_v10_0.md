# Taxo 10.0

**Stable release — 19.09.2026**

Taxo 10.0 завершує перевірочну лінію 9.1 і переводить накопичені зміни у стабільну експлуатаційну версію. Останній ручно перевірений кандидат — **v9.1-r9.8**. Попередня stable/rollback точка — **v9.0.1**.

## Основні зміни

### Робочий час і графіки
- один канонічний стан дня для «Табеля» і «Графіка водіїв»;
- точні часові частини, розділені зміни та переходи через 00:00;
- тривалість рахується як об'єднання інтервалів, без подвійного рахунку перекриття;
- нові перекриття блокуються, а історичні записи не переписуються автоматично;
- duration-only не перетворюється на вигаданий інтервал 08:00–16:00;
- місячний графік змінності має PDF графіка, PDF деталізації та пряме відкриття обох документів.

### Персонал
- окремий розділ «Персонал»;
- планування змін і відсутностей;
- режими 5/40, 6/40, 6/36, 6/24, підсумований та індивідуальний;
- внутрішнє сумісництво без дублювання ролі водія;
- тижневі/місячні баланси враховують індивідуальну норму та відсутності.

### П-5
- PDF та XLSX типової форми № П-5;
- повна легенда кодів 01–30;
- надурочні, нічні, вечірні та вихідні/святкові години;
- якщо є план без факту, Taxo питає оператора: підставити план, сформувати лише за фактом або скасувати;
- підставлений план завжди явно виділяється і пояснюється приміткою.

### Аудит і нормативний контроль
- центр «Аудит графіків…» перевіряє технічні помилки введення;
- окремий «Контроль №340» перевіряє нормативні показники;
- ці функції не змішуються;
- аудит підтримує legacy worklog із точними часовими полями.

### Шляхівки
- маршрути, автомобілі, нумерація, PDF, спідометр/пробіг та історія пробігу;
- лікар/механік визначається як один операційний slot за правилом **роль + дата графіка + номер зміни**;
- нічний рейс не підхоплює чергового наступної календарної дати;
- legacy-дублікати чергових показуються як конфлікт і мають бути виправлені вручну.

### Підтвердження діяльності
- архів із фільтром за водієм;
- опційний місяць/рік;
- новіші записи зверху;
- збереження ревізій та PDF.

### START / пакування
- START.bat працює у Windows-safe ASCII/CRLF;
- запуск прямо з неповного ZIP не доходить до pip, а показує інструкцію розпакування;
- START package перевіряється автоматично;
- робочі БД, SQLite, кеші, скани й персональні документи не включаються до релізних пакетів.

## Виконавчі пакети

Stable publisher формує:
- **Windows x64 Setup** — `Taxo_v10_0_Setup_Windows_x64.exe`;
- **Windows x64 Portable** — `Taxo_v10_0_Windows_x64_Portable.zip`;
- **macOS ARM64 Portable** — `Taxo_v10_0_macOS_arm64_Portable.zip`;
- **macOS Intel x86_64 Portable** — `Taxo_v10_0_macOS_x86_64_Portable.zip`;
- **START/source** — `Taxo_v10_0_START.zip`;
- SHA-256 manifests, включно з загальним `SHA256SUMS_v10_0.txt`.

## Перевірка перед stable

- ручний operational gate завершено на реальній Windows-базі;
- перевірено запуск START;
- перевірено місячний графік і відкриття деталізації;
- перевірено шляхівки та єдину пару чергових на одну зміну;
- regression suite виконується на Windows, macOS ARM64 та macOS Intel;
- stable artifacts збираються вже з commit у `main`.

## Дані та оновлення

- робоча БД не входить у пакет;
- 10.0 використовує наявне робоче сховище;
- існуючі історичні дані не потрібно вводити повторно;
- перед оновленням робочого середовища рекомендована резервна копія.

## Історія

Кандидати `v9.1-r5` … `v9.1-r9.8` залишаються історичними immutable контрольними точками. Вони не пересуваються і не перезаписуються.

Stable 10.0 стає новою основною експлуатаційною версією після успішної багатоплатформної збірки та публікації.
