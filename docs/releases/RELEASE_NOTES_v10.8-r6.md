# Taxo 10.8-r6 — fast-test

**Статус:** кандидат для тестування / prerelease.  
**База:** immutable `v10.8-r5`.  
**Stable:** `v10.3` не змінюється.

## Навіщо ця ревізія

`main.py` історично виріс до понад 15 000 рядків і одночасно містив запуск, UI, файлову інфраструктуру та багато прикладних сценаріїв. Це не було окремою runtime-помилкою, але стало ризиком для подальшої розробки: складніше локалізувати зміни, перевіряти залежності й уникати випадкових регресій.

Тому в `10.8-r6` почато **поступову модульність без великого переписування програми**.

## Що змінено

- створено окремий модуль `output_files.py`;
- з `main.py` винесено нейтральні helper-и роботи з вихідними файлами:
  - відкриття файла/папки системною програмою;
  - підбір шрифтів для PDF;
  - визначення file-access / locked-file помилок;
  - створення читабельної унікальної назви копії;
  - діалог `Повторити / Створити копію / Скасувати`;
  - дружні повідомлення про файлові помилки;
  - спільний цикл запису вихідних PDF/XLSX/інших файлів;
- у `main.py` збережено compatibility-wrapper для `write_output_file()`, тому старі call sites не переписувалися масово;
- `main.APP_VERSION` і `VERSION.txt` синхронізовано на `10.8-r6`;
- додано `tests/test_v10_8_r6.py` для контролю межі модульності й збереження поведінки;
- `START.bat` тепер явно перевіряє наявність `output_files.py` і `v1085_features.py`;
- source-package workflow також вимагає обидва ці runtime-файли, тому неповний пакет не може пройти перевірку.

## Що принципово НЕ змінювалося

- схема робочої БД;
- формат і місце робочих даних;
- plan/fact;
- Бланки підтвердження діяльності;
- роль водія;
- СТОІР;
- реєстр документів ТЗ;
- правила розрахунків робочого часу;
- користувацькі дані та їх міграція.

## Що перевірити вручну

1. Запуск `START.bat` з повністю розпакованого архіву.
2. Створення типових PDF/XLSX звітів.
3. Поведінку при спробі перезаписати файл, який відкритий в іншій програмі: `Повторити / Створити копію / Скасувати`.
4. Відкриття сформованих файлів системною програмою.
5. Базові робочі сценарії, особливо Бланки, табель, шляхові листи, документи ТЗ та СТОІР — вони не повинні відрізнятися від r5.

## Подальше розділення `main.py`

Не робити механічне масове дроблення. Наступні блоки можна виносити **окремими наступними ревізіями** після власного аудиту залежностей: backup/migration helpers, attestation query helpers, report/export infrastructure, великі UI workspace-блоки.
