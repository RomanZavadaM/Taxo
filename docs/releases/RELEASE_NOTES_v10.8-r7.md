# Taxo 10.8-r7 — fast-test

**Статус:** кандидат для тестування / prerelease.  
**База:** immutable `v10.8-r6`.  
**Stable:** `v10.3` не змінюється.

## Навіщо ця ревізія

Taxo продовжує активно розширюватися. Історично `taxo_app.py` накопичив десятки прямих import/install кроків і велику вкладену композицію revision-layer модулів. Така точка входу працювала, але погано масштабується: кожен новий модуль вимагав ще однієї ручної зміни entry point і створював ризик помилки в порядку підключення.

`10.8-r7` закладає контрольовану точку розширення без зміни бізнес-логіки.

## Що змінено

- додано `feature_layers.py` — впорядкований registry runtime feature layers;
- кожен layer має стабільний `feature_id`, installer, bootstrap-ознаку та domain metadata;
- registry перевіряє унікальність feature IDs, bootstrap-позицію та callable installers;
- `taxo_app.py` більше не містить довгу вкладену `install(...)` композицію;
- поточний `App` будується через один `install_feature_layers(core)`;
- історичний порядок підключення всіх наявних layer-ів збережено;
- `START.bat` і source-package verification явно вимагають `feature_layers.py`;
- додано `tests/test_v10_8_r7.py` для контролю registry semantics та install order;
- `docs/maintenance/AUDIT_EXTENSION_ARCHITECTURE_v10.8-r7.md` фіксує архітектурний напрям подальшого розширення.

## Архітектурне правило на майбутнє

Registry є точкою композиції, а не місцем бізнес-логіки. Нові великі функції мають створюватися як окремі domain/service/repository/UI модулі з малим installer, а не як нескінченне нарощування `main.py` або вкладених revision wrappers.

Наступні кроки повинні поступово зменшувати залежність нових модулів від глобального namespace `main` і вводити вузькі service/repository interfaces для взаємодії між доменами.

## Що НЕ змінювалося

- схема та формат робочої БД;
- робоче сховище користувача;
- plan/fact;
- Бланки підтвердження діяльності;
- роль водія;
- табель;
- СТОІР business rules;
- документи ТЗ;
- військовий облік;
- користувацькі дані та їх історія.

## Що перевірити вручну

1. Звичайний запуск Taxo через `START.bat`.
2. Відкриття основних розділів після запуску: Персонал, ТЗ, СТОІР, Документи, Табель.
3. Що порядок і наявність функцій не відрізняються від r6.
4. Базові сценарії Бланків, шляхових листів та СТОІР.

## Важливо

- це fast-test checkpoint;
- PR поточної ревізії не зливається в `main` без окремої команди власника;
- після видачі `v10.8-r7` будь-яка нова кодова зміна — тільки `10.8-r8`;
- робочі БД, скани, персональні документи та кеші до пакета не входять.
