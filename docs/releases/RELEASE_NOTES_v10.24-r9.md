# Taxo 10.24-r9 — збереження копій документів транспортних засобів

**Статус:** Test candidate. Stable/Latest не змінюється і залишається 10.24-r3.

## Підстава

27.11.2026 власник повідомив, що раніше внесені копії документів ТЗ, зокрема протоколи ОТК, виявилися недоступними. Аудит підтвердив дві небезпечні властивості попереднього механізму:

- БД зберігала тільки адресу внутрішньої копії Taxo, але не зберігала шлях до початково вибраного файла;
- інтерфейс показував «Копія: Є» за самим фактом непорожнього шляху в БД, навіть якщо файла на диску вже не було.

Окремо підтверджено, що копії документів ТЗ входили у звичайний backup тільки при явній відмітці «Копії документів транспортних засобів». Це правило вибору не змінюється, але вибраний backup тепер не може тихо пройти перевірку з відсутніми файлами.

## Що змінено

- нова або замінена копія документа завжди записується як Taxo-owned файл у `Data/VehicleDocuments/<vehicle_id>/<document_type>/...`;
- разом із внутрішнім шляхом зберігаються початковий source path, розмір і SHA-256 внутрішньої копії;
- список документів і загальний контроль показують фактичний стан: «Є», «Файл втрачено», «Копія пошкоджена», «Зовнішній файл» або «Немає»;
- відкриття копії перевіряє фактичну наявність та integrity, а не лише текстовий шлях;
- архівування запису не видаляє й не переносить bytes копії;
- backup із відміткою документів ТЗ перевіряє всі зареєстровані копії, включно з архівованими;
- якщо старий запис посилається на зовнішній файл або внутрішня копія зникла, але збережений source path ще існує, backup робить самодостатню керовану копію **всередині резервного архіву**, не змінюючи живу БД;
- restore архіву, який заявляє включення документів ТЗ, повторно перевіряє, що всі зареєстровані bytes реально відновлені.

## Важлива межа відновлення старих даних

Якщо старий запис уже не має доступного внутрішнього файла **і** початковий файл/старий backup також відсутній, Taxo не може відтворити втрачені bytes. r9 робить таку втрату видимою і не дозволяє назвати неповний архів повною перевіреною копією.

Для старих записів, де source path раніше взагалі не зберігався, він не може бути відновлений заднім числом. Після нового прикріплення r9 зберігає його разом із контрольними даними.

## Резервування

Поведінка галочки зберігається:

- без відмітки «Копії документів транспортних засобів» можна створити базовий backup БД;
- з відміткою backup повинен містити всі фактично зареєстровані копії документів ТЗ або завершитися явною помилкою;
- «Повна копія / перенесення» робочого сховища як і раніше переносить весь `Data/VehicleDocuments`.

## Regression

Додано наскрізні сценарії:

1. протокол ОТК → керована копія → source path/hash/size;
2. непорожній шлях у БД + відсутній файл → «Файл втрачено»;
3. архівований документ → backup з vehicle documents → restore → файл доступний і SHA-256 збігається;
4. непоправно відсутня копія → selected full backup відхиляється;
5. legacy external reference → selected backup забирає bytes у резерв і restore перетворює його на workspace-копію;
6. змінена/пошкоджена керована копія виявляється й не проходить повний backup.
