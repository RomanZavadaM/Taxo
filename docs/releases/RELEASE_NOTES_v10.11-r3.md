# Taxo 10.11-r3 — захист факту та безпечне перепланування персоналу

**Дата:** 06.11.2026  
**Статус:** **PRERELEASE / кандидат для користувацького тестування**.  
**Stable:** без змін, `v10.10-r5`.  
**Попередній immutable candidate:** `v10.11-r2`.

## Зміни

- Дія «План → факт» більше не перезаписує вже наявний факт.
- Перед копіюванням плану у факт Taxo просить явне підтвердження.
- У факт записуються лише вибрані дні, де факт відсутній і є робочий план.
- Після операції Taxo окремо показує кількість записаних днів, захищених наявних фактів, днів без плану та днів поза періодом роботи.
- Детальне перепланування персоналу тепер замінює стару зміну атомарно: видалення старого плану та запис нового є однією безпечною операцією.
- Якщо новий запис не проходить перевірку БД, старий план зберігається, batch відкочується, а користувач отримує помилку замість оманливого «Пропущено».
- Додані поведінкові regression tests для обох сценаріїв втрати/пошкодження даних.

## Що не змінюється

- `v10.11-r2` не переписується і не пересувається.
- Stable `v10.10-r5` не змінюється.
- UX Issue #164, CI optimization PR #142/#152, dependency/security update та захист історії тахографічних протоколів залишаються окремими напрямками.
- План і факт надалі лишаються різними сутностями; r3 лише прибирає небезпечний шлях, який міг записати план поверх існуючого факту.

## Перевірки

До публікації кандидата обов'язкові:
- повний START regression suite;
- Windows x64;
- Windows 7 x64;
- macOS ARM64;
- macOS Intel x86_64;
- перевірка r3 package naming;
- immutable publisher gate на exact source.

Нові r3 regression tests перевіряють:
- існуючий факт не змінюється дією «План → факт»;
- порожній факт отримує план без переписування інших ручних полів;
- невдала заміна плану залишає стару зміну без змін;
- успішна заміна створює рівно одну нову зміну.
