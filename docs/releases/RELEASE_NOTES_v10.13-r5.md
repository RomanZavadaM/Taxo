# Taxo 10.13-r5 — спільний вибір працівників, водіїв і ТЗ

**Статус:** candidate / у перевірці.  
**Stable не змінюється:** v10.12-r10.

## Що змінено

У Taxo введено спільний контракт вибору сутностей із робочої бази для наказів, інструктажів та майбутніх документів.

### Працівники

- кожен вибір містить стабільний внутрішній ID Taxo;
- для відображення використовуються ПІБ, табельний номер і посада;
- РНОКПП та реєстровий ідентифікатор доступні для точного зіставлення/пошуку, але РНОКПП не друкується автоматично у підготовчі списки;
- якщо табельного номера немає, у підписі показується маскований РНОКПП;
- однакові видимі підписи додатково розрізняються внутрішнім ID.

### Водії

- список водіїв є фільтром спільного списку працівників;
- механіки/інші працівники не потрапляють до driver-only вибору;
- неактивні записи не пропонуються для нового документа, але лишаються доступними для історичного режиму.

### Транспортні засоби

- кожен вибір містить стабільний ID;
- у підписі використовуються держномер, марка/модель та VIN;
- VIN і держномер входять до пошукових/ідентифікаційних реквізитів;
- неактивні ТЗ не пропонуються для нового документа, але не втрачаються з історії.

## Де підключено

- наказ про закріплення ТЗ за водіями;
- вкладка «Закріплення водіїв»;
- «Експлуатація → Інструктажі та журнали».

Підготовчий CSV інструктажу для нового структурованого вибору містить ПІБ, табельний номер і «Код Taxo». РНОКПП не виводиться в цей файл без окремої юридичної потреби.

## Історія та майбутні документи

Спільний choice-row уже містить snapshot однозначних реквізитів. Це основа для наступного етапу, де конкретні накази зберігатимуть власний знімок реквізитів на момент введення документа в дію, щоб майбутня зміна картки не переписувала історичний документ.

## Що навмисно НЕ змінено

- немає електронних підписів інструктажів;
- «вибрано / надруковано» не означає «проведено»;
- не змінюються plan/fact;
- stable/release/security не змінюються;
- схема робочої БД у цьому кроці не мігрується.

## Перевірки r5

Нові regression-тести покривають:
- однакові ПІБ;
- табельний номер і РНОКПП як ідентифікаційні реквізити;
- driver-only фільтрацію;
- VIN/держномер ТЗ;
- active/historical режим;
- підготовчий CSV без автоматичного друку РНОКПП;
- синхронізацію версії та START-пакета.

Повний Windows / Win7 / macOS / START CI має пройти до інтеграції.
