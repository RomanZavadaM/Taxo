# Taxo 10.17-r10 — тестова portable-збірка

**Тип випуску:** Pre-release для приймання інтерфейсу. **Не stable.** Робоча стабільна версія — `v10.16-r8`.

## Що перевіряти

Цей випуск накопичує зміни тестових ревізій `10.17-r1…r10`. Рекомендований порядок ручного приймання:

1. **Реєстри ТЗ, маршрутів, працівників, наказів і водіїв:** натисніть заголовки колонок і перевірте сортування за датою, числом, статусом та текстом; після «Оновити» і перемикання фільтрів має зберігатися обраний рядок.
2. **Історія наказу:** сортуйте чотири заголовки, особливо «Коли» для кількох змін протягом одного дня; закрийте через «Закрити» та X, перевірте повторне відкриття і незмінність записів.
3. **Тахограф:** «Скасувати» і X у редакторі інтервалу, збереження лише явною дією, підтвердження видалення та повторне розпізнавання без втрати ручних записів.
4. **Маршрути, СТОІР, налаштування й документи операцій:** зрозуміле повернення або «Закрити» у дочірніх вікнах; «Скасувати» не має записувати незбережені значення.
5. **Пули номерів шляхівок:** окремо перевірте «Деактивувати / активувати пул» (зміна стану) та «Закрити вікно» (лише вихід без зміни стану).

## Умови приймання

- Тестовий випуск не змінює стабільний `v10.16-r8`; код тестової гілки не інтегрований у `main`.
- Нового функціоналу бібліотеки шаблонів і сховища документів немає — цей напрям відкладено.
- Автоматичні тести не замінюють ручної перевірки Windows DPI 100/125/150 %, фокуса, нижніх кнопок і збереження чернеток.
- Для тестування використовуйте portable-пакет відповідної ОС. Перед заміною робочої програми зробіть окрему резервну копію даних, тестуйте на копії сховища, не змішуйте стабільний і тестовий каталоги.
- Вміст пакетів, checksum SHA256 та підтримувані платформи перевіряє штатний workflow публікації. Доки GitHub Release з активами не з'явився в Releases, це **кандидат**, а не опублікований тестовий випуск.
