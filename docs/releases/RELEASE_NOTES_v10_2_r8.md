# Taxo 10.2-r8

**Candidate — unified personnel planning — 21.09.2026**

10.2-r8 прибирає паралельні входи до планування персоналу без міграції або дублювання даних.

## Що показав аудит

- водійський графік зберігається окремо у водійській моделі, бо містить маршрут, транспорт, робочі інтервали та керування;
- загальний план персоналу і старе вікно випуску вже використовували одну таблицю `employee_shifts`;
- проблема була не у двох базах, а у двох UI-шляхах і різних правилах запису;
- старе ручне вікно випуску рахувало `planned_hours` як весь проміжок «від–до», тоді як загальний планувальник уже враховував неоплачувану перерву.

## Нова логіка

- **Водії:** плануються тільки через **«Графік водіїв»**.
- **Лікар, механік, диспетчер та інші ролі:** плануються через **Персонал → Планування → «Робочі зміни персоналу — масово…»**.
- **Оперативний день випуску:** показує ті самі `employee_shifts` для конкретної дати та використовується для контролю і внесення/коригування факту.
- Старий виклик `show_dispatch_month_planner` залишений лише як сумісний маршрут і перенаправляється у загальний планувальник.
- Окрема кнопка старого місячного планувальника у вікні випуску більше не додається.

## Розрахунок часу

При коригуванні зміни з оперативного вікна доступне поле **«Неоплачувана перерва, хв»**. Планові години рахуються як тривалість зміни мінус ця перерва, тому редагування дня не повертає помилкові 9:00 для типової зміни 08:00–17:00 з годинною перервою.

## Дані та сумісність

- схема БД не змінюється;
- існуючі `employee_shifts` не переносяться і не дублюються;
- факт не підміняється планом;
- stable `v10.1` не змінюється;
- попередній `v10.2-r7` лишається immutable checkpoint.

## Що перевірити вручну

1. **Персонал → Планування**: видно окремий вхід у графік водіїв, загальні робочі зміни та оперативний день випуску.
2. Для механіка/лікаря/диспетчера створити масовий план і переконатися, що він з'явився в оперативному дні.
3. В оперативному дні відредагувати зміну, внести факт і перевірити, що план не губить неоплачувану перерву.
4. Для працівника з роллю водія загальний планувальник повинен направляти у «Графік водіїв», не створюючи дубль у `employee_shifts`.
5. Перевірити шляхівку: лікар/механік підтягуються з того самого плану.
