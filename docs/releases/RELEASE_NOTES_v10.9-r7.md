# Taxo 10.9-r7 — СТОІР: одометр і прогноз ТО

Fast-test ревізія поверх immutable `v10.9-r6`. Stable `v10.3` не змінюється.

## Що виправлено

- `work_date` використовується як fallback-дата одометра, якщо `reading_at` відсутній;
- новіший фактичний показник зі шляхівки більше не програє старішому ручному запису лише через порожній `reading_at`;
- середній добовий пробіг використовує валідні хронологічні точки з тим самим fallback-правилом;
- historical lookback прив'язаний до останньої фактичної точки, а не до `date.today()`;
- прогноз ТО відраховується від дати останнього надійного показника одометра;
- одиничний очевидний стрибок пробігу не повинен домінувати середній при достатній історії;
- повністю недатований показник не використовується для вигадування прогнозної дати.

## Що навмисно не змінено

ТО-1 і ТО-2 залишаються окремими циклами, як у чинній моделі. r7 не вводить неузгоджене правило «ТО-2 автоматично скидає ТО-1». Це окреме бізнес-рішення.

## Технічна реалізація

- additive layer `v1097_stoir_odometer.py`;
- без зміни схеми БД;
- без переписування історії одометра;
- поведінкові SQLite-тести в `tests/test_v10_9_r7.py`;
- START/package guards вимагають r7 runtime.

Перед видачею: exact-head regression/START + Windows + macOS x86_64/arm64. Злиття в `main` — тільки за окремою прямою командою власника.
