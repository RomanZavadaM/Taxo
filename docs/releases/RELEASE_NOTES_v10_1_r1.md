# Taxo 10.1-r1

**Candidate / test checkpoint — 20.09.2026**

Taxo 10.1-r1 — перша кодова контрольна точка після stable 10.0. Вона призначена для ручної перевірки перед будь-яким рішенням про промоцію у stable. Stable `v10.0` і його історичні artifacts не змінюються.

## Виправлення ролі «Водій»

Причину дефекту локалізовано в legacy-синхронізації `drivers` → `employees` / `employee_roles`.

Раніше під час `init_db()` для вже існуючого працівника `employees.active` перезаписувався значенням `drivers.active`, а роль `Водій` безумовно додавалася назад у `employee_roles`.

У 10.1-r1:
- `employees.active` є окремим статусом працевлаштування і не переписується з `drivers.active`;
- `drivers.active` означає тільки поточний стан ролі водія;
- `driver_end_date` зберігається окремо;
- завершена роль не відновлюється під час стартової legacy-синхронізації;
- звичайне редагування картки працівника не очищає історичну дату завершення ролі;
- поновлення працівника після звільнення не вмикає роль водія автоматично;
- при знятті активності водія з картки водія запитується дата завершення ролі;
- додано точкове відновлення старого bug-стану: якщо є `driver_end_date`, немає `dismissal_date`, а `employees.active` було помилково скинуто старим startup sync, працівник повертається у стан «Працює» без ролі «Водій».
