# Taxo 10.14-r6 — повернення видимого масового закріплення ТЗ/водіїв

**Дата:** 09.11.2026  
**Тип:** candidate / Feature Loss hardening.  
**Stable:** без змін, `v10.14-r4`.

## Виявлений дефект

Під час експлуатаційного тестування власник не зміг скористатися раніше перевіреним механізмом вибору кількох водіїв і транспортних засобів у наказі про закріплення.

Сам механізм і дані не були видалені. Багатовибірні списки залишалися в коді, але після розширення форми наказу опинилися нижче великих текстових полів у діалозі без прокрутки. На робочому розмірі вікна вони могли бути поза видимою областю.

## Виправлено

- блок «Закріплення в цьому наказі» перенесено вище текстових полів наказу;
- форма адаптована до робочого мінімального розміру;
- багатовибір ТЗ і водіїв лишився тим самим: 1 ТЗ → кілька водіїв або N ТЗ ↔ N водіїв;
- окремий маршрут «Закріплення водіїв → Додати багато…» збережено;
- `operations.assignment_bulk` додано як окрему критичну функцію до Feature Loss registry;
- новий live regression перевіряє не лише наявність написів, а фактичну видимість списків у межах вікна та видимість кнопки «Додати багато…».

## Чому старий захист пропустив

Старий тест 10.13-r4 перевіряв, що підписи «Транспортний засіб» і «Водій із бази водіїв» існують у дереві Tk. Він не перевіряв `winfo_ismapped()` і фізичне розташування елемента в межах діалогу. Крім того, Feature Loss registry захищав загальний маршрут «Експлуатація», але не масове закріплення як окрему функцію.

Це r6 виправляє для даного механізму. Загальне посилення meta-gate ведеться в Issue #275.
