# Taxo 10.18-r8 — читання вмісту шаблонів

**Статус:** тестовий кодовий checkpoint (не Stable і не офіційний Pre-release). База: перевірений `10.18-r7` exact head `aed893047ef8853d2c8c9ef96e7d58603ad66c55`.

## Нове

- Двічі клацнути на шаблон у бібліотеці, натиснути Enter або кнопку «Переглянути шаблон».
- Окреме read-only вікно із двома вкладками: **«Текст та додатки»** і **«Поля для заповнення»**.
- У текстовому перегляді показуються вихідні структурні блоки без підстановки даних: заголовки, абзаци, списки, таблиці, динамічні таблиці як позначки джерел, місця підпису, додатки та великі інструкції.
- Перелік змінних відокремлено від самого тексту; позначено обов'язковість, тип та опис поля.
- Файли читаються виключно з перевіреного manifest за ID/ревізією; читач повторно перевіряє розмір та SHA-256, не переходить поза корінь бібліотеки.
- Функція не створює документ, наказ, чернетку, не відкриває файл у редакторі й не змінює шаблон; жодних записів у SQLite, PaperDocuments, Output або журнал наказів.
- Окремі `template_library_preview.py` і `template_library_preview_ui.py`; в `main.py` — тільки версія, не реалізація.
- Синтетичні тести на текст, таблиці, змінні, додатки, великі інструкції, відмову за невірним SHA-256/ID/небезпечним шляхом.

## Межі та приватність

Бібліотека зі знеособленими документами зберігається **лише у приватному пакеті власника**, розпакованому в обраному робочому сховищі Taxo: `<workspace>/TemplateLibrary`. Тексти приватних шаблонів, їхні ідентифікатори, персональний Windows-шлях і приватна адреса репозиторію **не включаються** в цей публічний code/CI/release. Для CI використані вигадані fixtures, не матеріали підприємства.

Значення `AVAILABLE` підтверджує лише поточну технічну перевірку читача. Перегляд не означає юридичної чинності, затвердження власної редакції, перевіреного підпису або друкарської відповідності DOCX/PDF.

## Що тестувати вручну

1. В «Експлуатація → Документи → Бібліотека шаблонів…» переконатись у наявності **28 шаблонів**.
2. Двічі натиснути на короткий наказ — побачити текст, списки, примітки, реквізити.
3. Відкрити довгу інструкцію і квартальну програму — перевірити повний текст, додатки та прокручування, без зависання головного вікна.
4. Вкладка «Поля для заповнення» — побачити тип і обов'язковість змінних.
5. Перевірити X і «Закрити», повторне відкриття перегляду, пошук/категорії/сортування в бібліотеці.
6. Після перевірки накази та бази лишаються незмінними.

Після успішного exact-head CI можна видавати окремий Portable candidate; Stable/Latest `v10.18-r3` лишається незмінною. Незавершені GitHub Pre-release r5–r7 не трактувати як опубліковані — перевірити фактичну чергу релізів перед публікацією.
