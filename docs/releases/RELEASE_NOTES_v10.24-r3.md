# Taxo 10.24-r3 — робочі журнали та картка кореспонденції

**Stable/Latest з 23.11.2026 за прямим рішенням власника.** Exact source `c9cb6b7787d991c5ce612ceec1efb32ecc90891d`; 8 canonical assets; `prerelease=false`; GitHub Latest.

10.24-r3 додає користувацький інтерфейс поверх уже перевірених r1 registry та r2 attachment APIs. Ця ревізія не змінює правила нумерації, не додає автоматичне надсилання і не вигадує факти отримання/відправлення.

## Що додано

- окремий модуль `correspondence_ui.py`, без розростання `main.py` та старих модулів наказів;
- видимий пункт лівого меню «Кореспонденція» через окремий feature-layer;
- strict live route `correspondence.center`, захищений від майбутнього «зникнення» функції;
- одне resizable вікно «Кореспонденція» з вкладками «Вхідні» / «Вихідні»;
- sortable журнали: реєстраційний номер, дата, кореспондент, тема, строк, стан, кількість вкладень;
- пошук по номеру/кореспонденту/темі/змісту/відповідальному/стану;
- точний фільтр за датою, штатний календар, «Сьогодні» та «Усі дати»;
- детальна картка вибраного листа з окремими semantic dates, зовнішнім номером, змістом, способом, відповідальним, строком, станом, response/related links та кількістю вкладень;
- форми «Новий вхідний», «Новий вихідний» і «Відповісти»;
- X і «Скасувати» захищають незбережені введені дані;
- порожня дата відправлення залишає вихідний лист лише `registered` — Taxo не називає його надісланим автоматично;
- окремий діалог вкладень з «Активні» / «Історія», додаванням файла або live DocumentVault link, відкриттям після integrity verification та history-only «Прибрати»;
- кнопка «Відкрити документ» для явно прив'язаного готового документа;
- physical reachability regression на viewport 760×520: ключові дії не обрізані;
- cleanup відкладеного пошукового refresh при закритті вікна, без Tk callback-хвостів.

## Важливі межі

- UI працює тільки через r1/r2 доменні API; не переписує registry напряму;
- вкладення не означає sent/received/delivered/signed;
- реєстрація вихідного листа без sent_date не означає фактичного відправлення;
- немає e-mail automation, OCR, зовнішнього AI, AI APPLY або фізичного purge;
- explicit mark-sent / mark-received transitions, cases/threads і зовнішні інтеграції — окремі наступні ревізії;
- Stable/Latest змінюється тільки окремим рішенням власника; таке рішення для r3 отримано 23.11.2026.
