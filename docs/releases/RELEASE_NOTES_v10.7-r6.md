# Taxo 10.7-r6 — candidate release notes

**Статус:** candidate / fast-test, не stable.  
**Дата підготовки:** 29.09.2026.  
**Stable line не змінюється:** `v10.3`.

## Основна тема

Безпечний порядок автоматичного резервного копіювання відносно 48-місячного retention.

## Підтверджений дефект E4

Під час ініціалізації бази `purge_old()` виконувався раніше за `auto_backup_database()`. Через це дані, що саме цього запуску переходили за 48-місячну межу зберігання, могли бути фізично видалені ще до створення автоматичної резервної копії.

## Виправлення

- спочатку виконується узгоджений SQLite backup;
- лише після успішної спроби backup запускається retention purge;
- строк зберігання 48 місяців не змінено;
- склад таблиць retention не змінено;
- логіка plan/fact не змінюється.

## Окремо перевірено E3

Глобальний writer-баг `водій + зміна персоналу = подвійний план` не підтверджено. Для точних часових меж конфлікт перетину вже блокується. Без доказів не вводимо штучне правило `max()` замість сумування, оскільки дві непересічні частини роботи в один день можуть бути коректними.

## Regression safeguards

`tests/test_v10_7_r6.py` перевіряє:

- backup викликається раніше за retention purge;
- 48-місячний cutoff збережений;
- r6 runtime layer встановлений outermost;
- поточна ідентичність кандидата — 10.7-r6.

## Не змінюється цим кроком

- stable `v10.3`;
- видані immutable checkpoints до `v10.7-r5` включно;
- plan/fact;
- кадрові історичні звіти r5;
- накази/експлуатація r4.

## Після r6

Наступна кодова ревізія — `10.7-r7`: оформлення PDF наказів, включно з усуненням буквальних тегів на кшталт `<b>№ ...</b>` і перевіркою всього шаблону на подібні артефакти.
