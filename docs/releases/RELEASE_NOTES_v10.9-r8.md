# Taxo 10.9-r8 — Накази: незмінність і закріплення

Fast-test ревізія поверх immutable `v10.9-r7`. Stable `v10.3` не змінюється.

## Що виправлено

- затверджений або підписаний наказ більше не можна звичайно редагувати;
- скасований наказ не можна повторно затвердити;
- непереданий `control_employee_id` не очищає відповідального;
- закріплення ТЗ/водія під затвердженим або підписаним наказом незмінні;
- конфліктні одночасні закріплення одного водія за різними ТЗ у новому наказі блокують затвердження;
- однозначне попереднє чинне закріплення завершується новим наказом без переписування старого затвердженого наказу;
- `active_driver_assignments()` враховує окремий факт припинення попереднього закріплення.

## Історична цілісність

Для завершення попереднього закріплення r8 використовує additive таблицю `vehicle_driver_assignment_endings`. Старий наказ і старий рядок `vehicle_driver_assignments` не переписуються; новий наказ створює окремий операційний факт припинення.

## Технічна реалізація

- runtime layer `v1098_orders_immutability.py`;
- additive schema change без перезапису існуючих даних;
- поведінкові SQLite-тести `tests/test_v10_9_r8.py`;
- START/package guard вимагає r8 runtime.

Перед видачею: exact-head source/START + Windows + macOS x86_64/arm64. Злиття в `main` — тільки за окремою прямою командою власника.
