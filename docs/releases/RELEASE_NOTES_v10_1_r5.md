# Taxo 10.1-r5 — candidate

**Дата:** 20.09.2026  
**Stable baseline:** Taxo 10.0  
**Previous immutable candidates:** v10.1-r1, v10.1-r2, v10.1-r3, v10.1-r4

## Причина

Під час ручної Windows-перевірки r4 виявлено помилку навігації: пункт **«Звіти»** у головному sidebar викликав детальний табель як нове велике branded-вікно, яке виглядало як ще одна копія Taxo. Повторні виклики могли створювати кілька таких вікон.

## Виправлено

- «Звіти» **не відкриває нову копію** application shell;
- звіти відкриваються як внутрішня сторінка основної робочої області;
- «Працівники» після звітів гарантовано повертає у реєстр працівників;
- активний пункт sidebar синхронізується з прихованою сторінкою «Працівники / Звіти»;
- детальний табель персоналу став single-instance: повторний виклик піднімає вже відкрите вікно;
- з окремого табеля прибрано дубльований sidebar і декоративний «другий головний екран»;
- у детальному табелі додано явну кнопку «Закрити».

## Збережено

- driver-role fix;
- KPI реєстру;
- PDF / Excel / П-5;
- місячний баланс і контроль;
- затверджений text-free логотип;
- робоче сховище і БД без міграції.

## Gate

Перед merge у main потрібні автоматичні regression checks та **ручна Windows-перевірка** навігації: «Звіти → Працівники → Звіти», повторне відкриття детального табеля та відсутність дубльованого повного shell.
