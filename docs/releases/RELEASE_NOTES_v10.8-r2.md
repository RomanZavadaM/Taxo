# Taxo 10.8-r2 — candidate release notes

## Автоматична перевірка фактично видимих функцій

10.8-r2 продовжує виправлення інтерфейсу 10.8-r1 і додає перевірку не лише наявності коду, а й фактичної поведінки Tk-інтерфейсу.

CI тепер запускає regression suite у віртуальному графічному середовищі Xvfb. Це дозволяє створювати справжні Tk/ttk-віджети та виявляти ситуації, коли функція лишилася в коді, але кнопка стала невидимою або розмітка зламалася після накладання новішого feature layer.

### Runtime smoke для вкладки «Транспорт»

Автоматично перевіряється, що:

- панель **«Картка транспортного засобу»** створюється без конфлікту `pack/grid`;
- видимі всі основні дії: **«Нове авто»**, **«Редагувати»**, **«Документи ТЗ»**, **«Контроль документів»**, **«Вивести з експлуатації»**, **«Оновити»**;
- кожна кнопка викликає свій початковий callback, а не тільки існує в коді;
- на вузькому вікні кнопки переносяться на кілька рядків, але не зникають;
- новіші дії реєстру/ТЦК можуть співіснувати з основними діями без повторення старої геометричної помилки.

## Постійний контракт інтерфейсу

Додано `v1082_features.py` з явним контрактом критичних точок входу для:

- картки транспортного засобу;
- реєстру документів ТЗ;
- основних розділів навігації.

Цей контракт призначений для наступних UI-ревізій: якщо подальше перевикладання або новий feature layer сховає одну з критичних дій, CI має зупинити збірку.

## Перевірка

Після виправлення історичного identity-тесту 10.8-r1 повний набір тестів разом із новими Tk runtime smoke tests проходить у Xvfb. Бізнес-логіка, схема БД і межа plan/fact у цій ревізії не змінюються.

Stable `v10.3` не змінюється. `v10.8-r1` лишається незмінним історичним fast-test. Після видачі `v10.8-r2` наступна зміна коду — `10.8-r3`.
