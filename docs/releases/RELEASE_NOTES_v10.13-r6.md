# Taxo 10.13-r6 — структуровані працівники й ТЗ у наказах

**Статус:** integrated у `main`; exact-main перевірки PASS; не stable і не окремий release.  
**Exact product:** `a3f4e7e924f8d4c7389b28dc659c2f1e72e210da` (PR #249).  
**Stable не змінюється:** v10.12-r10.

## Мета

Розвинути спільні selector-и 10.13-r5 до реального документного механізму: не лише показати працівника/ТЗ у списку, а прикріпити конкретні записи бази до наказу та зберегти їхні реквізити на момент формування чернетки.

## Що додано

- новий структурований перелік **«Учасники / ТЗ»** для наказів;
- масовий вибір кількох працівників або кількох ТЗ;
- пошук за ПІБ, табельним №, ідентифікаційними реквізитами, держномером та VIN;
- роль / призначення в наказі для вибраної групи;
- для стажування та місць відпочинку employee-selector використовує саме базу водіїв;
- кожний зв'язок зберігає stable Taxo ID і frozen snapshot реквізитів;
- зміна ПІБ, табельного №, держномера, моделі чи VIN у живій картці надалі не переписує історичний перелік наказу;
- неактивні сутності не можна додати до нового наказу;
- видалення зі чернетки не стирає факт з історії змін;
- після введення наказу в дію структурований перелік незмінний;
- наказ про закріплення ТЗ/водіїв лишається на спеціалізованій моделі й окремій вкладці.

## PDF

Якщо наказ має структурованих працівників/ТЗ, PDF отримує окрему сторінку:
**«Структурований перелік працівників і транспортних засобів»**.

Для працівника друкуються ПІБ, роль і табельний № / Taxo ID; повний РНОКПП автоматично не друкується.

Для ТЗ друкуються держномер, марка/модель, роль і VIN.

## Схема даних

Additive table `operations_order_entities`:
- order_id;
- entity_type;
- entity_id;
- role;
- snapshot_json;
- sequence_no;
- note;
- timestamps.

Існуючі накази та робочі дані не переписуються.

## Межі

- це не електронний підпис;
- це не доказ фактичного проведення інструктажу;
- plan/fact не змінюється;
- stable/release/security не змінюються;
- для наказу про закріплення зберігається спеціальна таблиця `vehicle_driver_assignments`.
