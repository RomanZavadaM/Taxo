# Taxo 10.13-r9 — виправлення після ручного тестування r8

**Статус:** fast-test candidate.  
**Stable не змінюється:** v10.12-r10.

## Виправлено за скрінами власника

### 1. Створення наказу

Старий шаблонний шар наказів не приймав новий параметр серії нумерації й падав з повідомленням про `order_series`.

r9 передає серію нумерації через цей шар до актуальної логіки створення наказу.

### 2. Дублікати закріплень

Сирий SQLite-текст `UNIQUE constraint failed...` більше не повинен виходити користувачу.

- одиночне додавання дубліката дає людське повідомлення;
- при масовому додаванні вже наявна пара пропускається, а нові пари додаються;
- редагування рядка в дублікат теж блокується людським поясненням.

### 3. Нумерація наказів

Стартові / наступні номери були сховані у вкладці «Відповідальні».

У реєстрі наказів додано пряму кнопку **«Нумерація наказів…»**. Вона відкриває видимий блок **«Нумерація наказів»** з:
- наступним № робочого / експлуатаційного наказу;
- наступним № кадрового наказу;
- коротким поясненням, що тут можна продовжити існуючий паперовий журнал з потрібного номера.

### 4. Фокус головного вікна

Після повного завантаження Taxo одноразово:
- розгортає головне вікно;
- піднімає його вперед;
- коротко вмикає topmost;
- забирає focus;
- через 250 мс вимикає topmost.

Тобто застосунок виходить на передній план, але не лишається «завжди поверх усіх».

## Режим тестування

За рішенням власника для швидкого функціонального тесту достатньо **START-збірки через `START.bat`**. Portable/installer лишаються для більших checkpoint/stable перевірок.

## Regression r9

Нові тести покривають:
- `order_series` у legacy template wrapper;
- людське повідомлення при одиночному дублікаті;
- пропуск дубліката при bulk add без втрати нових пар;
- прямий вхід у «Нумерація наказів…»;
- одноразове foreground/focus після запуску;
- r9 VERSION/START identity.
