# Taxo 10.6-r2 — нерегулярні поїздки та адаптивне «Про програму»

**Дата:** 28.09.2026  
**Тип:** candidate / fast-test  
**Stable baseline:** Taxo 10.3

## Шляхові листи

Виправлено хибне припущення, що кожен виїзд автобуса повинен мати регулярний маршрут із каталогу.

### Регулярний маршрут

Для дня з реальним `route_id` зберігається чинна сувора перевірка маршруту, крайніх точок, графіка прямого/зворотного напрямку та інших маршрутних реквізитів.

### Нерегулярна поїздка

Якщо робочий день водія не має каталожного `route_id`, стандартна дія **«Сформувати / видати PDF»** переходить у сценарій нерегулярної поїздки замість помилки «бракує маршруту».

Підтримуються, зокрема:

- замовлення;
- одноразовий маршрут;
- розвозка;
- поїздка по місту;
- поїздка по області;
- міжобласна поїздка;
- інша разова робота автобуса.

Правила:

- плановий час виїзду/повернення береться з графіка водія;
- якщо автобус ще не прив'язаний до робочого дня, його можна вибрати прямо у діалозі видачі;
- вибір автобуса записується як **планове призначення на день**, а не як фактична тахографічна подія;
- поле **«Поїздка / замовник»** є вільно редагованим;
- типове значення — **«по області»**;
- зворотний бік не заповнюється фіктивним маршрутним розкладом/точками;
- фактичний час і тахографічний облік не переписуються.

Нижню окрему дію перейменовано на **«Інша поїздка / замовлення…»**, щоб вона не створювала враження, що нерегулярна робота автобуса є помилковим «поза маршрутом» станом.

## Вікно «Про програму»

- зменшено надлишкову висоту верхнього банера;
- ущільнено внутрішні відступи body/footer;
- вікно дозволено змінювати за розміром;
- на невисокому/масштабованому екрані застосовується додаткове компактне компонування;
- нижня кнопка **«Закрити»** повинна залишатися повністю видимою.

## Межа plan / fact

10.6-r2 не змінює базову модель Taxo:

- графік/призначення автобуса = план;
- тахограф і фактичні джерела = факт;
- нерегулярна шляхівка не робить план фактом і не переписує `fact_work_*`.

## Нумерація

- `10.6-r1` вже виданий та immutable;
- цей крок — **10.6-r2**;
- після видачі 10.6-r2 наступна кодова ревізія — **10.6-r3**.
