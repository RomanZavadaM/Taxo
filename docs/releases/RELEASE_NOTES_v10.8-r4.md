# Taxo 10.8-r4 — candidate release notes

## Окремий центр СТОІР

Розпочато окремий контур технічної експлуатації ТЗ без перевантаження існуючого центру наказів/експлуатації.

Новий робочий центр **«СТОІР»** має окремі вкладки:

- **Огляд**;
- **Пробіг / одометр**;
- **ТО і ремонти**;
- **Технічний контроль (ОТК)**.

## Пробіг як джерело планування ТО

Taxo використовує вже наявний журнал `vehicle_odometer_readings`, який формується з фактичних показників одометра/шляхових листів. Паралельне поле «поточний пробіг» не створюється.

Для планування ТО зберігається профіль ТЗ:

- легкові автомобілі та автобуси — базово ТО-1 5 000 км, ТО-2 20 000 км;
- вантажні автомобілі, автобуси на вантажній базі та відповідні категорії — базово ТО-1 4 000 км, ТО-2 16 000 км;
- можна застосувати індивідуальний профіль за документацією виробника.

Якщо Taxo не знає одометр останнього підтвердженого ТО, наступний поріг не вигадується, а позначається як невідомий до внесення факту.

## ТО і ремонти

Додано реєстрацію експлуатаційних подій:

- ТО-1;
- ТО-2;
- сезонне ТО;
- ремонт.

Для події зберігаються дата, одометр, опис робіт, виконавець, посилання на документ/наряд та примітка. Цей блок є фундаментом для наступних ревізій із заявками на несправності, дефектними відомостями та ремонтними нарядами.

## Обов'язковий технічний контроль

Внутрішній ключ документа `inspection` збережено для сумісності існуючих БД, але користувацька назва уточнена до **«Протокол ОТК / перевірки технічного стану»**.

ОТК не прирівнюється до ТО-1/ТО-2:

- копія протоколу зберігається у **«Документи ТЗ»**;
- у СТОІР показується його номер, строк чинності, статус і видавець;
- ОТК не скидає лічильник ТО;
- виконання ТО не продовжує строк ОТК.

## Regression / package safety

Додано тести для:

- нормативних/індивідуальних профілів ТО;
- використання останнього фактичного одометра;
- розрахунку наступного ТО;
- заборони вигадування плану без останнього ТО;
- окремої сутності ОТК;
- чотирьох окремих вкладок СТОІР;
- runtime та START/source-package guards.

Історичний regression 10.8-r3 збережено як функціональний anchor і більше не блокує законний перехід на 10.8-r4.

## Межі r4

У цю ревізію навмисно не включаються шини, АКБ, агрегати, склад запчастин та перебудова планування персоналу. Вони не повинні перевантажити перший робочий контур СТОІР.

Stable `v10.3` не змінюється. Після видачі `v10.8-r4` наступна кодова зміна — тільки `10.8-r5`.
