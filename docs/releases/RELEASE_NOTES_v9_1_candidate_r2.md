# Taxo 9.1 candidate r2

r2 виправляє помилку, знайдену під час реальної перевірки місячного планування персоналу випуску.

## Виправлено

У r1 попередній перегляд вважав місце випуску частиною унікальності зміни. Насправді таблиця `employee_shifts` має унікальний ключ:

`employee_id + role + work_date + shift_no`

Через це працівник, який уже мав ту саму роль/дату/номер зміни в іншому місці, міг пройти попередній перегляд, але впасти під час INSERT з `sqlite3.IntegrityError`.

r2:
- перевіряє існуючу зміну працівника незалежно від місця;
- не перезаписує факт;
- без явного прапорця пропускає вже заплановану зміну працівника;
- з прапорцем замінює лише план цього самого працівника;
- не видаляє план іншого працівника, якщо цільова зміна вже зайнята;
- повторно перевіряє стан безпосередньо перед записом;
- кожен день записує під SQLite SAVEPOINT, тому окремий конфлікт не валить весь місячний пакет і не стирає старий план.

## Інше

Збережено всі зміни r1:
- місячний огляд лікаря/механіка;
- масові шаблони графіка;
- покращена шапка та виділення введених даних у шляховому листі;
- виправлення `bad window path name` при відкритті табеля персоналу.

Схема БД не змінюється.
