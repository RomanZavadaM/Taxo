# Taxo 10.11-r6 — безпечний output / restore / backup disclosure

**Дата:** 06.11.2026  
**Статус:** робочий candidate slice; ще не release.  
**Stable:** без змін, `v10.10-r5`.  
**Попередній immutable candidate:** `v10.11-r5`.

## Межі r6

Це окремий hardening-slice за Issue #175. Він не змішується з UX Issue #164 або CI optimization #142/#152.

### Атомарний запис PDF/XLSX та інших вихідних файлів

Спільний `write_output_file()` тепер спочатку створює sibling temp-файл із тим самим розширенням. Лише після успішного завершення writer-а temp атомарно замінює цільовий файл.

Якщо writer падає після часткового запису, попередній правильний PDF/XLSX залишається недоторканим.

### Restore main DB

Якщо відновлення нової БД не вдалося і аварійне повернення safety backup також падає, друга помилка більше не приховується. Taxo повідомляє composite failure, показує обидві помилки та точний шлях до страхової копії.

Успіх restore не заявляється без перевіреного стану.

### Прозорий склад backup

`Data/EmployeeDocuments` і раніше фактично завжди входив у workspace backup. r6 виправляє пояснення користувачу:

- у блоці «Завжди» прямо показані обидві БД і документи працівників;
- ZIP без додаткових галочок більше не має назви `Taxo_backup_db_...`;
- базова назва — `Taxo_backup_core_with_employee_documents_...`;
- фінальне повідомлення прямо перелічує документи працівників як обов'язкову частину копії.

Склад backup не розширюється і не звужується цією зміною — виправляється прозорість.

## Regression

Додано `tests/test_v10_11_r6.py`:
- невдалий writer не пошкоджує існуючий output;
- успішний writer замінює файл через temp із правильним suffix;
- подвійна помилка restore не приховується і вказує safety backup;
- backup UI і filename явно відображають EmployeeDocuments;
- `main.APP_VERSION` і `VERSION.txt` = `10.11-r6`.
