# Taxo 10.7-r5 — candidate release notes

**Статус:** candidate / fast-test, не stable.  
**Дата підготовки:** 29.09.2026.  
**Stable line не змінюється:** `v10.3`.

## Основна тема

Історичні кадрові звіти не повинні втрачати працівника лише тому, що на поточну дату він уже звільнений.

## Підтверджений дефект E2

У кадрових звітах був правильний date-aware предикат `employee_employed_on(...)`, який враховує дату прийняття і дату звільнення. Але перед ним при `active_only=True` виконувався SQL-фільтр `employees.active=1`.

Через це працівник, який працював у звітному місяці, але був звільнений пізніше, міг повністю зникнути зі старого звіту П-5 / аудиту табеля / тижневого балансу.

## Виправлення

Додано зовнішній compatibility layer `v1075_features.py`:

- історичні report collectors спочатку завантажують і активні, і неактивні записи;
- належність працівника до звітного періоду визначає вже існуюча функція `employee_employed_on(...)` за датами прийняття/звільнення;
- працівник включається у звіт, якщо був працевлаштований хоча б один день у відповідному періоді;
- після дати звільнення він у наступні періоди не потрапляє;
- поточні UI-списки активних працівників не змінюються: `_all_employee_rows(..., active_only=True)` не патчиться.

Виправлення охоплює:

- `collect_personnel_week_balance`;
- `collect_personnel_timesheet_audit`;
- `collect_p5_data`;
- PDF/XLSX П-5, які використовують `collect_p5_data` як джерело.

## Regression safeguards

`tests/test_v10_7_r5.py` перевіряє:

- date-aware межі прийняття/звільнення;
- відсутність current-active SQL prefilter у report path;
- незмінність current-active UI helper;
- встановлення r5 outer runtime layer;
- синхронність `main.APP_VERSION` і `VERSION.txt`.

## Не змінюється цим кроком

- plan/fact робочого часу;
- правила підстановки плану у П-5;
- тахографічні дані;
- накази/закріплення r4;
- stable `v10.3`;
- issued checkpoints до `v10.7-r4` включно.

## Після r5

Продовжити аудит:

1. E3 — можливий подвійний план `водій + зміна персоналу`;
2. E4 — порядок `purge_old()` відносно резервного копіювання;
3. далі межі тижня/режимів і activity register plan/fact.
