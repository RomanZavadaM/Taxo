# Taxo 10.9-r2 — цілісність історії шляхових листів

## Основне

Ревізія 10.9-r2 закриває критичні ризики втрати або повторного використання історії виданих шляхових листів, виявлені зовнішнім аудитом і підтверджені на актуальному runtime Taxo.

- 48-місячне очищення табеля більше не видаляє `worklog`, якщо на нього вже посилається видана шляхівка;
- додано незворотний реєстр `waybill_number_history` для історично використаних пар «серія + номер»;
- при першому запуску r2 реєстр безпечно заповнюється з поточних `waybills` та append-only журналу `waybill_events`, тому зберігаються також анульовані/перевиданні номери, які вже могли зникнути з поточного рядка;
- повторне використання такого номера блокується на рівні SQLite, а не лише UI;
- фізичне видалення водія або `worklog`, пов'язаних із виданою шляхівкою, блокується до появи окремого юридично безпечного архівного workflow;
- новий захист винесено в окремий `waybill_integrity.py`, не роздуваючи `main.py`;
- додано поведінкові SQLite-тести retention, повторного номера та каскадного видалення.

## Тестова політика

За результатами двох частин зовнішнього аудиту критичні бізнес-інваріанти перевіряються поведінковими тестами на тимчасовій реальній SQLite-БД. Старі тести, що назавжди фіксували конкретну «останню» feature-layer або поточний номер попередньої ревізії, переведено у historical-anchor semantics без послаблення функціональних перевірок.

На candidate-head `4708330587024fc94dda58621cd46fee0faf744e` source regression: **734/734 OK**; START source archive успішно сформовано та перевірено. Windows/macOS PR-gates виконуються окремо перед immutable issuance.

## Сумісність і дані

- формат існуючих рядків `waybills` та `waybill_events` не ламається;
- історичні номери лише додаються в незворотний індекс, дані користувача не видаляються;
- retention для звичайного табеля зберігає 48-місячне правило, але робить виняток для джерел уже виданих шляхівок;
- видалення працівника/водія з юридично значущою історією тепер повинно оформлятися деактивацією/архівуванням, а не фізичним DELETE;
- `main` не змінюється до окремої прямої команди власника на merge.

## Наступні аудиторські кроки

Після r2 у backlog зафіксовано: `valid_from` і весь період рейсу для документів ТЗ; контроль щоденного/щотижневого відпочинку; тахограф/60-денний реєстр; норма П-5; пробіг СТОІР; незмінність затверджених наказів; централізовані schema migrations та connection/error-handling hardening.
